# Свой движок

Движок означает программу, которая держит модель на видеокарте и отвечает на запросы.
На Looma Float есть движки площадки. Автор может опубликовать свой: например, движок
под карты, с которыми движки площадки не работают, или под свой формат весов.

На своём движке автор собирает [свои модели](own-models.md). Открытый движок берут в
свои модели и другие авторы.

Код движка работает на чужих машинах, поэтому его читает площадка. Одобренная сборка
получает подпись, и узел запускает только подписанный код. Владелец узла сам решает,
принимать ли код авторов: это настройка в разделе «Узлы» кабинета автора.

Все действия есть в кабинете автора, в разделе «Движки», и в CLI: команда
`looma engine`. ИИ-агент делает то же инструментами `looma_engine_*`.

## С чего начать {#start}

В репозитории Looma Kit лежит учебный движок
[`engines/echo`](https://github.com/LoomaFloat/looma-kit/tree/main/engines/echo). Он
повторяет последнее сообщение, работает без весов и без видеокарты, а весь договор с
площадкой помещается в одном файле. Скопируйте папку в свой репозиторий и запустите у
себя:

```sh
cd engines/echo
LOOMA_SERVE_PORT=8000 python -m echo_engine.server
```

```sh
curl http://127.0.0.1:8000/v1/chat/completions \
  -d '{"messages":[{"role":"user","content":"привет"}]}'
```

Рядом лежит настоящий движок,
[`engines/llm`](https://github.com/LoomaFloat/looma-kit/tree/main/engines/llm): чат на
открытых весах с HuggingFace через `transformers`. Он скачивает веса, грузит модель на
видеокарту и отвечает целиком и потоком, со счётом токенов. С него удобно начинать
движок, которому нужны веса и видеокарта. Тот же движок образом лежит в
[`engines/llm-box`](https://github.com/LoomaFloat/looma-kit/tree/main/engines/llm-box).

Что в нём стоит перенять:

- порт начинает слушаться сразу, а модель грузится рядом: пока она не готова, `/health`
  отвечает 503, и площадка видит, что служба жива и занята загрузкой;
- если модель не загрузилась, движок пишет причину в лог и завершается. Висеть с
  закрытым здоровьем хуже: по такой реплике не понять, что случилось;
- закачка весов повторяется при обрыве сети, а загрузчик `xet` выключен
  (`HF_HUB_DISABLE_XET=1`): на части машин он обрывает большие файлы;
- `torch` в зависимостях назван без версии: узел сам берёт сборку под свой драйвер.

## Что должен уметь движок {#contract}

Движок запускается одним процессом на Python на одном узле. Модель встаёт на узел
целиком: разрез по нескольким узлам есть только у движков площадки. Если Python и
ревью кода не подходят, движок приносят образом: раздел [Движок-образ](#image).

| Что | Как |
|---|---|
| Порт | слушать порт из `LOOMA_SERVE_PORT` на `127.0.0.1` |
| Готовность | `GET /health` отвечает 200 и `{"status": "ok"}`, когда модель готова. Пока она грузится, отвечайте 503 |
| Запросы | `POST /v1/chat/completions` в формате OpenAI, целиком и потоком событий |
| Учёт | в ответе есть `usage` с `prompt_tokens` и `completion_tokens`. В потоке `usage` едет в последнем событии перед `[DONE]` |

Движок автора пока отвечает только на чат. Эмбеддинги, изображения и видео считают
движки площадки.

Что движок получает в переменных окружения:

| Переменная | Что в ней |
|---|---|
| `LOOMA_SERVE_PORT` | порт, который нужно слушать |
| `LOOMA_MODEL_ID` | имя модели в каталоге: его же движок возвращает в поле `model` |
| `LOOMA_MODEL` | репозиторий весов на HuggingFace, если модель его называет |
| `LOOMA_ENGINE_OPTIONS` | поля рецепта одним JSON-объектом |
| `LOOMA_EXTENSIONS` | пакеты расширений JSON-списком |
| `HF_HOME` | общий кэш весов на узле: скачанное один раз не качается заново |
| `CUDA_VISIBLE_DEVICES` | видеокарта, которую движку выделил узел |

Веса движок скачивает сам. Токена HuggingFace площадка движку автора не передаёт,
поэтому репозиторий весов должен быть открытым.

## Манифест {#manifest}

В папке движка лежит файл `looma-engine.yaml`:

```yaml
name: echo
title: Учебный движок
text: Повторяет последнее сообщение.
kinds: [text]
package: echo_engine
command: [python, -m, echo_engine.server]
requirements: requirements.txt
weights: none
extensions: true
requires:
  device: [cuda, mps, cpu]
  ram_gib: 1
fields:
  - key: repeat
    label: Сколько раз повторить
    type: int
    min: 1
    max: 5
    default: 1
```

| Поле | Что значит |
|---|---|
| `name` | имя движка: строчная латиница, цифры и дефис. В каталоге движок называется `автор/имя` |
| `title`, `text` | название и одна-две фразы о движке: их видят авторы в форме модели |
| `kinds` | чем движок отвечает. Сейчас только `text` |
| `package` | папка с кодом рядом с манифестом. Её файлы едут на узел, остальное из репозитория не едет |
| `command` | команда запуска целиком, первой частью `python`. Параметры в неё не подставляются: всё нужное приходит в переменных окружения |
| `requirements` | зависимости: файл рядом с манифестом или список строк. Только пакеты, без параметров pip. Пакет из своего файла называют так: `имя @ ссылка` |
| `weights` | `none`, если движок работает без весов; `hf`, если модель называет репозиторий на HuggingFace |
| `extensions` | `true`, если движок принимает [расширения](#extensions) |
| `requires` | что движку нужно от узла, таблица ниже |
| `fields` | поля, которые автор модели задаёт в форме: таблица ниже |

Требования к узлу (`requires`):

| Поле | Что значит |
|---|---|
| `device` | на чём движок работает: `cuda`, `mps` (Mac с Apple Silicon), `cpu`. По умолчанию `cuda` |
| `vram_gib` | сколько свободной памяти одной видеокарты нужно, ГиБ. Автор модели может назвать больше под свою модель |
| `ram_gib` | оперативная память узла, ГБ. У движка-образа это ещё и предел памяти службы |
| `cuda` | версия CUDA драйвера, не ниже которой движок работает, например `12.1` |
| `gpu` | названия карт, для которых движок написан, например `[V100, P100]` |

По этим требованиям площадка выбирает узел и объясняет, почему движок не встал.

Поле рецепта (`fields`) описывается так же, как у движков площадки:

| Поле | Что значит |
|---|---|
| `key` | ключ: строчная латиница, цифры, подчёркивание. Под этим ключом значение придёт в `LOOMA_ENGINE_OPTIONS` |
| `label`, `hint` | подпись и подсказка в форме |
| `type` | `text`, `int` (с `min`, `max`, `step`), `bool` или `select` (с `options`) |
| `default` | значение, если автор модели поле не трогал |
| `level` | `basic` видно сразу, `advanced` лежит в тонкой настройке |

Сборка небольшая: до 400 файлов и 8 МБ, файл до 1 МБ. Это код, веса в неё не кладут.

## Движок-образ {#image}

Движок можно принести не кодом на ревью, а образом. В манифесте вместо `package`,
`command` и `requirements` стоит блок `image`, рядом лежит `Dockerfile`. Площадка сама
собирает образ из папки движка и запускает его в песочнице на своих машинах.

```yaml
name: echo-box
title: Учебный движок в песочнице
kinds: [text]
image:
  dockerfile: Dockerfile     # по умолчанию Dockerfile в папке движка
  port: 8000                 # порт службы внутри образа
  command: [python, -m, echo_engine.server]   # не задан: ENTRYPOINT и CMD образа
weights: none
requires:
  device: [cuda, cpu]
  ram_gib: 1
  cpus: 1
```

Чем эта форма отличается от движка с ревью:

| | Движок с ревью | Движок-образ |
|---|---|---|
| Что приносит автор | пакет на Python и список зависимостей | папку с Dockerfile: любой язык и любые библиотеки |
| Проверка | ревью читает код, одобренная сборка подписывается | ревью кода нет: версию одобряет сборка образа |
| Где работает | на узлах сети, которые принимают код авторов, и на своих узлах | только на машинах площадки, в песочнице |
| Сеть | как у обычной задачи узла | только через прокси площадки, порты 80 и 443 |
| Видеокарта | да | да, одна на реплику: раздел [Видеокарта в образе](#image-gpu) |

Договор службы тот же (`/health`, `/v1/chat/completions`, `usage`), с двумя отличиями:
слушать нужно на всех адресах (`0.0.0.0`), а порт берётся из манифеста и приходит в
`LOOMA_SERVE_PORT` и `PORT`.

Память и процессор службы в песочнице ограничены тем, что названо в `requires.ram_gib` и
`requires.cpus`. Если они не названы, служба получает 1 ГиБ и одно ядро.

### Веса и постоянный каталог {#image-cache}

Корень службы в песочнице живёт столько же, сколько реплика: после перезапуска он пуст.
Чтобы веса не качались заново, у движка-образа на каждой машине есть свой постоянный
каталог.

| Что | Как |
|---|---|
| Где он | `/cache`, тот же путь приходит в `LOOMA_CACHE_DIR` |
| Кэш HuggingFace | `HF_HOME` уже указывает внутрь каталога. Движку на `transformers` или `huggingface_hub` делать ничего не нужно |
| Чей он | у каждого движка свой. Версии и реплики одного движка делят его, чужой движок его не видит |
| Сколько живёт | переживает перезапуск реплики на той же машине. На другой машине каталог свой и поначалу пустой |
| Гарантии | это кэш, а не хранилище. Давно не тронутый каталог площадка убирает, когда на машине кончается место. Движок должен уметь скачать веса заново |

Веса движок скачивает сам, через прокси площадки, поэтому репозиторий должен быть
открытым. Значение `HF_HOME`, заданное в образе, площадка заменяет своим.

Сборка идёт на машине площадки и занимает несколько минут. Её ход виден в разделе
«Движки» и в `looma engine`: «образ собирается», «образ собран» или «образ не собран» с
причиной и концом лога сборки. Папка движка для сборки: до 5000 файлов и 64 МБ; веса в
образ не кладут, движок скачивает их при запуске.

Образец лежит в [`engines/echo-box`](https://github.com/LoomaFloat/looma-kit/tree/main/engines/echo-box).
Подаётся такой движок той же командой, что и движок с ревью.

Модель на движке-образе нельзя держать «только на своих узлах»: вне машин площадки
такой образ не запускается.

### Видеокарта в образе {#image-gpu}

Движок-образ получает видеокарту, если назвал её в требованиях:

```yaml
requires:
  device: [cuda]
  vram_gib: 16     # свободная память одной карты, которая нужна реплике
  ram_gib: 24      # оперативная память службы
  cpus: 4
```

Что нужно знать автору:

| Что | Как |
|---|---|
| Сколько карт | одна на реплику. Внутри она всегда под номером 0, какой бы по счёту ни была на машине. `CUDA_VISIBLE_DEVICES` площадка не ставит |
| Чужие карты | не видны и не открываются: в песочнице есть только устройство своей карты |
| Драйвер | в образ его не кладут. Библиотеки драйвера (`libcuda.so.1`, `libnvidia-ml.so.1` и другие) и `nvidia-smi` площадка подключает сама в `/usr/local/nvidia`, той же версии, что на машине. Пути уже стоят в `LD_LIBRARY_PATH` и `PATH` |
| Что кладут в образ | свои библиотеки для расчётов: PyTorch, CUDA Toolkit, всё, чем движок считает. Образы `nvidia/cuda` и `pytorch/pytorch` подходят как основа |
| Память | `ram_gib` у движка на видеокарте обязателен. В песочнице это предел: службу, которая возьмёт больше, площадка остановит. Называйте столько, сколько нужно на загрузку модели, а не на работу в покое |
| Что доступно от карты | расчёты (CUDA) и сведения о карте (`nvidia-smi`, NVML). Графики и аппаратного кодирования видео в песочнице нет |
| Время карты | записывается за реплику так же, как у любой модели на видеокарте |

Если в `device` названы и `cuda`, и `cpu`, движок встаёт и на машину с видеокартой, и на
машину без неё. На машине с видеокартой он получает карту, и время карты записывается,
даже если движок ею не пользуется. Движку, которому карта не нужна, оставьте `[cpu]`.

Версия драйвера на машинах площадки может смениться. Не привязывайте образ к номеру
драйвера: привязывайте к версии CUDA, под которую собраны ваши библиотеки, и называйте
её в `requires.cuda`.

Образец лежит в [`engines/card-box`](https://github.com/LoomaFloat/looma-kit/tree/main/engines/card-box):
служба отвечает, какую карту видит и сколько на ней памяти.

## Публикация {#publish}

Движок публикуют из открытого репозитория на GitHub. Нужны три вещи: ссылка на
репозиторий, коммит целиком (40 знаков) и папка, если манифест лежит не в корне.
Ветку или тег назвать нельзя: под тем же именем завтра окажется другой код, а
проверяется один определённый.

```sh
looma engine submit --repo https://github.com/anna/engines \
  --commit 4f0c2b7e9a1d3c5b6e8f0a2b4c6d8e0f1a3b5c7d --path engines/echo
```

Версия уходит на ревью площадки. Ревью читает код целиком, а у следующих версий ещё и
отличия от прошлой одобренной. Что смотрят:

- движок делает то, что о нём написано, и ничего сверх этого;
- зависимости названы явно и ставятся из известных источников;
- код не трогает чужие данные на узле и не выходит в сеть без нужды.

Решение видно в кабинете и в `looma engine`: версия одобрена или отклонена с причиной.
Исправленный код подают новой версией, она проходит ревью заново.

Одобренная версия получает подпись площадки. Подписаны файлы сборки, команда запуска
и список зависимостей. Узел сверяет с подписью все три, поэтому на машину владельца
едет ровно то, что прочитано.

## Модель на своём движке {#model}

На одобренном движке собирают модель: в кабинете автора это «Модели» → «Своя модель»,
в форме выбирается движок. В CLI:

```sh
looma model check --engine anna/echo            # есть ли узлы, на которых движок встанет
looma model add parrot --engine anna/echo --set repeat=2
```

Если движок работает с весами, модель называет репозиторий: `--repo владелец/модель`.
Формат весов задаёт движок, площадка их не разбирает. Память видеокарты под модель
называет поле `vram_gib`: `--set vram_gib=12`.

Версия движка закрепляется за моделью. Когда выходит новая версия, работающая модель
остаётся на прежней. Чтобы перейти на новую, модель заводят заново.

Модель на движке можно держать только на своих узлах: флаг `--own` или выбор «только
на моих узлах» в форме. Тогда время видеокарт не записывается, а ваши вызовы такой
модели бесплатны: доля автора движка с них не берётся. Какие движки встанут на вашу
машину, показывает раздел «Узлы»: [Свои узлы](https://docs.loomafloat.ru/authors/nodes/#движок-на-своём-узле).

```sh
looma model add parrot --engine anna/echo --own
```

Модель на движке автора встаёт только на узлы, которые принимают код авторов и чья
программа узла проверяет подписи. Время
видеокарт под её реплики идёт автору модели в расходы, как у любой своей модели.
Дальше с ней работают как обычно: цена, публикация, вызовы из сервисов. Об этом
статья [Свои модели](own-models.md).

## Доля автора {#fee}

Автор движка может назначить долю: сумму за 1M входных и выходных токенов, которая
идёт ему с вызовов моделей, собранных на движке. Доля задаётся при подаче версии и
закрепляется за ней. Чтобы поменять долю, подают новую версию; модели на прежней
версии остаются с прежней долей.

```sh
looma engine submit --repo https://github.com/anna/engines \
  --commit 4f0c2b7e9a1d3c5b6e8f0a2b4c6d8e0f1a3b5c7d --fee in=1 --fee out=3
```

Когда доля берётся, а когда нет:

| Кто зовёт модель | Доля автору движка |
|---|---|
| другой автор или клиент | берётся |
| владелец модели, модель работает на узлах сети | берётся |
| владелец модели, модель работает только на его узлах | не берётся: это личное использование |
| автор движка зовёт свою модель на своём движке | не берётся |

Владелец модели видит долю в форме и не может назначить цену ниже неё: иначе он
доплачивал бы за каждый чужой вызов. Сколько начислено с начала месяца, показывает
раздел «Движки» и `looma engine`. Выплат пока нет: это учёт.

## Открыть движок авторам {#share}

Одобренный движок сначала видит только его автор. Открытый движок появляется в форме
модели у всех авторов:

```sh
looma engine open echo
looma engine close echo
```

## Расширения {#extensions}

Расширение добавляет код к движку: свой обработчик, свой набор узлов графа. Оно
проходит тот же путь, что движок: репозиторий, коммит, ревью, подпись. Движок должен
объявить `extensions: true`.

В папке расширения лежит `looma-extension.yaml`:

```yaml
name: upper
title: Заглавные буквы
extends: anna/echo
package: echo_upper
requirements: []
```

`extends` называет движок, для которого расширение написано. Пакет расширения
ложится рядом с пакетом движка и импортируется по имени. Какие расширения выбрал автор
модели, движок узнаёт из `LOOMA_EXTENSIONS`. Как движок их вызывает, решает его автор:
учебный движок зовёт у каждого расширения функцию `transform(text)`.

```sh
looma engine submit --repo https://github.com/anna/engines \
  --commit 4f0c2b7e9a1d3c5b6e8f0a2b4c6d8e0f1a3b5c7d --path engines/echo-upper --extension
```

Расширение пишут для своего движка или для открытого чужого. Одобренное расширение
появляется в форме модели флажком.

## Команды {#commands}

| Команда | Что делает |
|---|---|
| `looma engine` | свои движки и расширения: версии и решения ревью |
| `looma engine submit --repo … --commit … [--path …] [--extension] [--fee in=… --fee out=…]` | подать версию на ревью; `--fee` задаёт долю автора в рублях за 1M токенов |
| `looma engine show <имя>` | движок подробно |
| `looma engine open <имя>`, `close <имя>` | открыть движок другим авторам или закрыть |

Инструменты для ИИ-агента: [MCP-сервер](mcp.md).

## Что стоит знать {#limits}

- Код движка открыт: репозиторий публичный, и владелец узла видит всё, что работает
  на его машине. Прятать в движке нечего.
- Отозванная версия снимается с узлов сразу. Модели на ней перестают отвечать, пока их
  не заведут на другой версии.
- Движок работает на одном узле. Реплик у модели может быть несколько, каждая на своём
  узле.
- Пробного запуска перед одобрением пока нет: версия одобряется по коду.
