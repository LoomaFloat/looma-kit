# Студия изображений

Код сервиса «Студия изображений» из каталога Looma Float. Студия рисует изображение по
описанию словами и правит любое изображение из галереи по описанию правки. Сервис собран
из шаблона `image-studio` (`looma init -t image-studio`).

## Что умеет

- Изображение по описанию в одном из трёх форматов: 1024×1024, 1344×768 или 768×1344.
- Правка изображения из галереи словами, например «сделай фон закатным». Исходник
  остаётся, правка ложится рядом.
- Галерея в бакете сервиса (`data.bucket`), она переживает релизы и сон процесса. У
  каждого клиента каталога своя галерея: чужие изображения не видны и не правятся.
- Инструмент MCP `draw` для ИИ-агентов: описание приходит в `POST /api/draw`, в ответе
  само изображение (PNG). Оно же ложится в галерею клиента.
- Только для клиентов каталога (`access: clients`).

## Модели

| Шаг в `gpu` | Модель | Зачем |
|---|---|---|
| `draw` | `Qwen-Image-2.1` | изображение по описанию и правка изображения |

Другую модель укажите в `gpu.draw` и в константе `MODEL` в `studio.py`. Сервис вызывает
только модели из раздела `gpu`, остальные отвечают `403`. Имена моделей показывает
`looma models`.

## События

Событий нет. Вызовы модели записываются на клиента каталога (`looma.for_client`), а
отметок для учёта сервис не ставит.

## API

```
GET  /                страница
POST /api/generate    {"prompt", "size"?, "seed"?}  → {"id"}
POST /api/edit        {"id", "prompt"}              → {"id"}: правка изображения из галереи
POST /api/draw        {"prompt", "size"?}           → PNG: инструмент MCP draw
GET  /api/images      последние изображения с подписями
GET  /img/<id>.png    само изображение
```

## Файлы

```
looma.yaml         манифест: процесс, бакет, модель, инструмент MCP, карточка
studio.py          HTTP-сервер: страница, генерация, правка, галерея, инструмент draw
requirements.txt   boto3 для бакета
icon.png           иконка карточки
.loomaignore       что не едет в релиз: папка gallery/ и логи
```

## Подготовка

1. Установите CLI:

   ```bash
   uv tool install "git+https://github.com/LoomaFloat/looma-kit"
   ```

2. Войдите командой `looma login`. Откроется браузер на странице
   `console.loomafloat.ru/device`: подтвердите вход в кабинете автора, ключ сохранится
   сам.
3. Задайте своё имя в строке `name:` файла `looma.yaml`. Имена на Looma Float
   уникальны, а `looma-studio` занято этим сервисом в каталоге. `looma dev` и
   `looma deploy` заводят сервис под именем из манифеста, из него же получаются адреса.

## Запустить у себя

```bash
looma sdk                          # копия SDK в папке loomafloat/
pip install -r requirements.txt    # boto3 для бакета
looma dev                          # http://127.0.0.1:8080, бакет в Docker
```

Без Docker запустите `looma dev --no-data`: изображения будут ложиться в папку
`./gallery`. С `looma dev --docker` процесс идёт в образе, собранном как на площадке, и
ставить зависимости не нужно.

Модели настоящие: `looma dev` вызывает их dev-токеном сервиса, не больше 200 вызовов в
сутки. Клиента каталога у себя нет: все запросы идут от одного посетителя без входа, и
галерея у них общая.

## Выкатить

```bash
looma validate               # проверка манифеста и проекта без релиза
looma deploy                 # релиз на staging
looma check --env staging    # запрос к сервису: код ответа, время, начало ответа
looma promote                # перевести релиз со staging на prod
```

Если копии SDK в проекте нет, `looma deploy` положит её сам. `looma check` доходит до
процесса и при `access: clients`. Открыть staging в браузере: `looma open --env staging`,
витрина попросит войти. Логи: `looma logs --env staging`.

## Опубликовать

```bash
looma publish    # карточка и цены уходят на модерацию
looma listing    # состояние карточки и решение модерации
```

`looma publish` берёт раздел `listing` и цены из `events` в `looma.yaml` релиза на prod.
Решение модерации видно в кабинете автора и в `looma listing`. После одобрения карточка
появляется в каталоге.

## Цена

В примере событий нет, поэтому нет и цены. Чтобы брать плату за изображение, объявите
событие с полем `price`:

```yaml
events:
  - { name: picture, title: Изображение, price: 5 }
```

`price` задаёт цену за одно изображение в рублях, можно с копейками; число здесь только пример. Событие
нужно и отметить в коде: вызовите `looma.charge("picture", client)` в `studio.py`, когда
изображение для клиента каталога готово. Так отмечает ответ пример
[assistant](../assistant/).

Новая цена действует после модерации, а не после релиза: выкатите правку на prod
(`looma deploy`, `looma promote`), выполните `looma publish` и дождитесь одобрения.

Подробно: [Быстрый старт](https://docs.loomafloat.ru/authors/quickstart/),
[Клиенты и цены](https://docs.loomafloat.ru/authors/prices/).
