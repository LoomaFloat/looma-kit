# Раскадровка

Код сервиса «Раскадровка» из каталога Looma Float, его написал независимый автор. Сервис
снимает ролик со звуком по идее в одну строку и по очереди использует три модели:

| Шаг | Модель | Что делает |
|---|---|---|
| 1. Сценарий | `Qwen3.8-Flash-Next-NVFP4` | превращает идею по-русски в план кадра (настроение, камера, звук) и три промпта по-английски |
| 2. Кадры | `Qwen-Image-2.1` | рисует три варианта первого кадра. По желанию рисует два варианта последнего правкой выбранного первого, поэтому герои и стиль сохраняются |
| 3. Съёмка | `MiniMax-H3` | снимает ролик со звуком на 5 или 10 секунд. Первый кадр (и последний, если выбран) передаются в `conditions` |

На каждом шаге клиент выбирает сам: правит промпты, просит переписать сценарий, рисует
ещё варианты, снимает несколько дублей. Режим «Без остановок» проходит все шаги подряд,
так же работает инструмент MCP `make_video` для ИИ-агентов.

## Модели

| Шаг в `gpu` | Модель |
|---|---|
| `script` | `Qwen3.8-Flash-Next-NVFP4` |
| `frames` | `Qwen-Image-2.1` |
| `video` | `MiniMax-H3` |

Имя модели записано в двух местах: раздел `gpu` в `looma.yaml` и константы в начале
`pipeline.py`. Сервис вызывает только модели из `gpu`, остальные отвечают `403`. Чтобы
поменять модель, поменяйте её в обоих местах. Имена моделей показывает `looma models`.

## События

| Событие | Когда отмечается |
|---|---|
| `video` | готов дубль клиента каталога |

Событие отмечается с номером дубля (`id`), поэтому повтор не запишется дважды.

## Что внутри

```
looma.yaml          манифест: процесс, бакет, три модели, событие video, MCP, карточка
app.py              HTTP-сервер: страница, API проектов, файлы, инструменты MCP
pipeline.py         конвейер: проекты, три шага, опрос задания на видео
store.py            хранилище: бакет сервиса на площадке, папка ./data у себя
static/             страница без сборки: index.html, app.css, app.js, mark.svg
icon.png            иконка карточки (256×256)
requirements.txt    boto3 для бакета
.loomaignore        что не едет в релиз: папка data/, логи, .env
```

Других зависимостей нет: сервер на `http.server`, страница на чистом JS, модели
вызывает SDK `loomafloat`.

## Как устроено

- **Проект** хранится JSON-файлом в бакете: `c/<клиент>/<проект>/project.json`, рядом
  кадры `start-….png`, `end-….png` и дубли `take-….mp4`. Папка клиента получается хешем
  его псевдонима, поэтому чужие проекты не видны.
- **Сценарий и кадры** считаются в фоновом потоке процесса: запрос отвечает сразу,
  страница опрашивает проект раз в 2,5 секунды. Если процесс перезапустится посреди шага
  (новый релиз, сон), проект покажет «Шаг прервался» и кнопку «Повторить».
- **Ролик** считает площадка заданием `POST /v1/videos`. Проект помнит только номер
  задания. Процесс может уснуть (`min: 0`): следующий заход спросит площадку и заберёт
  готовый дубль в бакет.
- **Клиенты каталога.** С `access: clients` шлюз отправляет посетителя без входа войти
  на витрине. Каждый запрос приходит с заголовком `X-Looma-Client`, вызовы моделей идут
  на клиента (`looma.for_client`), готовый дубль отмечается событием `video`
  (`looma.charge`).
- **MCP.** Инструменты `make_video` и `video_status` описаны в `channels.mcp` манифеста.
  Площадка принимает вызов ИИ-агента с ключом клиента и делает POST на
  `/mcp/make_video` или `/mcp/video_status`.

## API

```
GET    /api/config                    форматы, длительности, модели
GET    /api/projects                  мои проекты
POST   /api/projects                  {"idea", "format", "seconds", "quality", "auto"}
GET    /api/projects/<id>             проект целиком
DELETE /api/projects/<id>             удалить с кадрами и роликами
POST   /api/projects/<id>/script      {"note"?}: переписать сценарий
PUT    /api/projects/<id>/script      {"title"?, "frame_prompt"?, "video_prompt"?, "end_prompt"?}
POST   /api/projects/<id>/frames      {"kind": "start" | "end"}: нарисовать варианты
PUT    /api/projects/<id>/frames      {"start"?, "end"?}: выбрать кадры ("end": "" без последнего)
POST   /api/projects/<id>/takes       снять дубль
GET    /media/<id>/<файл>             кадр или ролик (?download=1 скачивает файл)
```

`format`: `16:9`, `9:16`, `1:1`. `seconds`: 5 или 10. `quality`: `draft` (около 3
минут на 5 секунд) или `fast` (около 6 минут).

## Подготовка

1. Установите CLI:

   ```bash
   uv tool install "git+https://github.com/LoomaFloat/looma-kit"
   ```

2. Войдите командой `looma login`. Откроется браузер на странице
   `console.loomafloat.ru/device`: подтвердите вход в кабинете автора, ключ сохранится
   сам.
3. Задайте своё имя в строке `name:` файла `looma.yaml`. Имена на Looma Float
   уникальны, а `storyboard` занято этим сервисом в каталоге. `looma dev` и
   `looma deploy` заводят сервис под именем из манифеста, из него же получаются адреса.

## Запустить у себя

```bash
looma sdk              # копия SDK в папке loomafloat/
looma dev --no-data    # http://127.0.0.1:8080, без Docker
```

Проекты ложатся в папку `./data`, в релиз она не попадает. С бакетом в Docker:
`pip install -r requirements.txt && looma dev`. Остановить: Ctrl+C.

Модели настоящие: `looma dev` вызывает их dev-токеном сервиса, не больше 200 вызовов в
сутки. Клиента каталога у себя нет: все запросы идут от одного посетителя, и событие
`video` не отмечается.

## Выкатить

```bash
looma validate               # проверка манифеста и проекта без релиза
looma deploy                 # релиз на staging
looma check --env staging    # запрос к сервису: код ответа, время, начало ответа
looma promote                # перевести релиз со staging на prod
```

Площадка собирает образ (Python 3.12, `pip install -r requirements.txt`) и ставит релиз
на staging. Если сборка не удалась, CLI покажет хвост лога. Если копии SDK в проекте нет,
`looma deploy` положит её сам.

`looma check` доходит до процесса и при `access: clients`. Чтобы пройти путь клиента,
откройте staging в браузере: `looma open --env staging`. Витрина попросит войти, подойдёт
тот же аккаунт. Дальше:

1. Введите идею, например «Старый маяк в шторм», и нажмите «Написать сценарий».
2. Посмотрите сценарий, откройте «Промпты для моделей», попросите переписать.
3. Нажмите «Нарисовать кадры» и выберите один из трёх вариантов первого кадра. По
   желанию нарисуйте последний кадр.
4. Нажмите «Снять ролик». В режиме `fast` это около 6 минут на 5 секунд. Страницу можно
   закрыть: ролик появится в «Моих роликах».
5. Включите «Без остановок» и создайте второй проект: все шаги пройдут сами.

Первый заход может занять до двух минут: процесс спит без запросов (`min: 0`), модели
тоже могут просыпаться. Лог процесса в реальном времени: `looma logs --env staging -f`.

## Опубликовать

```bash
looma publish    # карточка и цены уходят на модерацию
looma listing    # состояние карточки и решение модерации
```

`looma publish` берёт раздел `listing` (название, описание, раздел «Видео», теги,
`icon.png`) и цены из `events` в `looma.yaml` релиза на prod. Решение модерации видно в
кабинете автора и в `looma listing`. После одобрения карточка появляется в каталоге, в
разделе «Видео».

На странице сервиса в каталоге клиент запускает его в браузере, видит инструменты MCP
`make_video` и `video_status` и выпускает ключ клиента. Там же страница показывает
готовую команду, которая подключает сервис к Claude. Дальше достаточно попросить агента:
«сними ролик про маяк в шторм». Агент вызовет `make_video`, получит номер проекта и
ссылку, а через несколько минут проверит готовность через `video_status`.

Статистика: `looma stats` показывает запросы по каналам, клиентов, события `video`,
вызовы трёх моделей и их себестоимость. То же видно в кабинете автора.

## Цена

В примере цены нет, событие `video` бесплатное. Чтобы брать плату за готовый дубль,
добавьте событию поле `price`:

```yaml
events:
  - { name: video, title: Ролик, price: 49 }
```

`price` задаёт цену за один дубль в рублях, можно с копейками; число здесь только пример. Новая цена
действует после модерации, а не после релиза: выкатите правку на prod (`looma deploy`,
`looma promote`), выполните `looma publish` и дождитесь одобрения.

## Обновить и убрать

Правка кода: `looma deploy`, проверка staging, `looma promote`. Карточку заново
публиковать нужно, только если поменялись `listing` или цены в `events`.

```bash
looma unpublish        # снять карточку с каталога
looma destroy --yes    # удалить сервис с бакетом, релизами и карточкой
```

## Если что-то не так

| Что видно | В чём дело |
|---|---|
| `looma deploy`: сборка не удалась | хвост лога в выводе; чаще всего опечатка в `looma.yaml` или `requirements.txt` |
| 503 на адресе | окружение остановлено или процесс падает: `looma status`, затем `looma logs --env staging` |
| «Модель недоступна сервису» | модели нет в разделе `gpu` манифеста или имя не совпадает с `looma models` |
| «Модель сейчас занята» | модель ответила 429, повторите через минуту |
| «Шаг прервался» | процесс перезапускался (новый релиз, сон) посреди сценария или кадров, нажмите «Повторить» |
| Ролик долго «в очереди» | модель снимает несколько роликов одновременно, остальные ждут своей очереди |
| 429 `dev_quota_exceeded` в `looma dev` | дневная квота dev-вызовов выбрана; она обновится в 00:00 UTC, на staging и prod не действует |

Подробно: [Быстрый старт](https://docs.loomafloat.ru/authors/quickstart/),
[Клиенты и цены](https://docs.loomafloat.ru/authors/prices/).
