# Свой движок на Looma Float

Движок: программа автора, которая работает на видеокарте и отвечает на запросы. Что она
считает и на каком языке говорит, решает автор: площадка даёт ей машину, передаёт
запросы как есть, поднимает реплики и считает вызовы. На движке собирают модель (`автор/
модель`), её зовут клиенты, сервисы и другие авторы.

Этот skill ведёт путь целиком: от чужого кода на CUDA до модели, которая отвечает на
своём узле автора, и дальше, по просьбе автора, в сеть. Что вообще подходит проекту
(модель каталога, своя модель, движок, сервис), решает skill `looma`; сюда приходят,
когда нужен свой код на карте.

## Шаг 0. Готовность

```bash
looma --version && looma whoami
looma model name            # имя автора: движок будет зваться автор/имя
looma node list             # есть ли свой узел на связи (MCP: looma_node_list)
```

Своего узла нет: предложи подключить (справка в skill `looma`, «Свои узлы»), если у
автора есть машина с NVIDIA. Без узла движок проверяется только у себя на машине, а в
сети он заработает после ревью.

## Шаг 1. Форма движка

Реши вместе с автором, по коду и по тому, как движок будут звать.

| Вопрос | Варианты |
|---|---|
| как зовут | `kinds: [api]`: свои адреса и данные (файлы, JSON, двоичное), общий случай; `kinds: [text]`: чат в формате OpenAI, модель видна в общем чате; можно оба |
| во что упакован | процесс на Python (`package`, `command`, `requirements`): на своих узлах без ревью, в сети после ревью; образ (`image` и Dockerfile): любой язык, только машины площадки, без ревью кода |
| веса | `weights: none` (движок сам знает, что грузить) или `hf` (модель называет репозиторий, он приходит в `LOOMA_MODEL`) |
| сколько длится вызов | секунды: обычный ответ; до 10 минут: площадка доведёт заданием сама; дольше: служба отвечает 202 и `Location` |
| что задаёт автор модели | поля `fields`: приходят в `LOOMA_ENGINE_OPTIONS` |
| что нужно от узла | `requires`: `device` (cuda, mps, cpu), `vram_gib`, `ram_gib`, `cuda`, `gpu` |
| плагины | `extensions: true`, если движок принимает расширения |

По умолчанию: процесс на Python со своим API. Образ берут, когда код не на Python, тянет
системные библиотеки или не укладывается в пакет, и автору хватает машин площадки. Граф
ComfyUI движком автора обычно не делают: его наборы узлов подключаются расширениями
движка площадки `comfyui` (раздел «ComfyUI» в `references/porting.md`).

## Шаг 2. Написать движок

Папка движка:

```
engine/
  looma-engine.yaml       манифест
  requirements.txt        зависимости: только пакеты, torch без версии
  my_engine/              пакет: только он едет на узел
    __init__.py
    server.py             служба
```

Что служба обязана площадке:

1. Слушать `127.0.0.1:$LOOMA_SERVE_PORT` (образ: `0.0.0.0`, порт из манифеста).
2. `GET /health`: 503, пока грузится; 200, когда готова. Порт открывать сразу, модель
   грузить рядом.
3. Не загрузилась: причину в лог (stderr) и выйти с ненулевым кодом. Висеть с закрытым
   здоровьем хуже.

Остальное её собственное: адреса, формат, своя единица счёта `X-Looma-Units`, ход
`X-Looma-Progress`. Манифест, переменные окружения, свой API, чат и долгие вычисления:
[Договор движка](references/contract.md). Каркасы службы: [Каркасы](references/templates.md).
Как переделать типичный код (пайплайн diffusers, модель transformers, ComfyUI, обучение,
обработка файлов, бинарник): [Переделка кода в движок](references/porting.md).

Правила переделки:

- код вычисления не переписывай: оберни его службой, вход и выход переведи в HTTP.
  На узел едет только папка `package`: код вычисления перенеси или скопируй в неё (с
  согласия автора, в плане). Допустимые правки самого вычисления: параметры вместо
  `sys.argv`, путь чекпойнтов в `LOOMA_CACHE_DIR`, продолжение с последнего чекпойнта,
  сообщение о ходе;
- секретов в коде движка нет и не будет: площадка их движку не передаёт; веса из
  открытых источников; для ревью репозиторий публичный;
- веса и данные в пакет не клади: движок скачивает их сам в `HF_HOME` или
  `LOOMA_CACHE_DIR` (каталог переживает перезапуск);
- `torch` в `requirements.txt` без версии: узел ставит сборку под свой драйвер.

## Шаг 3. Проверить у себя

```bash
cd engine && pip install -r requirements.txt
LOOMA_SERVE_PORT=8000 LOOMA_MODEL_ID=test python -m my_engine.server
curl -s localhost:8000/health
curl -s -X POST localhost:8000/<свой путь> -d '…'
```

Без видеокарты на машине проверь хотя бы старт, здоровье и адреса на маленькой модели
или на `device: cpu`. Ошибки импорта и опечатки дешевле найти здесь, чем на узле.

## Шаг 4. На свой узел, без ревью

```bash
looma engine try engine/                      # MCP: looma_engine_try
```

Папка упаковывается и становится новой версией, одобренной сразу. Работает она только на
узлах этой учётной записи; другим авторам не видна.

```bash
looma model add solver --engine anna/solver [--repo владелец/веса] [--set поле=значение]
looma model add solver --engine anna/solver --node home-1    # на конкретном своём узле
looma model show solver                       # реплика поднимается: «работает 1»
looma call anna/solver --path /tasks --data '{"x": 1}'       # свой API, JSON
looma call anna/solver --path /render --data-file sketch.png \
  --header "Content-Type: image/png" --out result.png       # двоичный вход и выход
looma call anna/solver "Привет"                              # чат
looma call anna/solver --path /render --async                # долгое: номер задания
looma job run_… --wait --out result.bin
```

Модель на версии без ревью сама становится «только на своих узлах». Если она не
отвечает:

```bash
looma model logs solver                       # MCP: looma_model_logs
looma node list                               # движок «не встанет»: причина в строке узла
```

Поправил код: `looma engine try engine/` даёт новую версию, модель переводится на неё:
`looma model set solver --engine-version latest`. Реплика заменяется сама. Цикл
«правка → try → engine-version → call» повторяй, пока ответы не станут верными. Проверяй
не только успешный путь: неверный вход (ответ 4xx не считается клиенту), большой файл,
отмена задания.

## Шаг 5. Подключить к сервису

Если у движка будет веб или клиенты витрины, сервис зовёт модель так же, как модели сети:
`gpu: { render: { model: anna/solver } }` и `looma.run("anna/solver", "/путь", …)` в коде.
Раскладка проекта и примеры: skill `looma`, «Сервис и движок вместе».

## Шаг 6. В сеть и другим авторам

Только по просьбе автора. Предложи, когда модель работает и нужна не только на его узлах.

1. На ревью, папкой из рабочей среды, как сервис (MCP: `looma_engine_submit` с
   `directory`):

   ```bash
   looma engine submit engine/ [--fee call=0.2 | --fee in=1 --fee out=3]
   looma engine show solver                    # ждёт проверки, одобрена или отклонена с причиной
   ```

   GitHub не нужен. Если код где-то опубликован, ссылку можно приложить: `--origin
   https://…` (площадка её не проверяет, только показывает рядом с версией). Автор держит
   код в открытом репозитории и хочет подавать коммитом: `looma engine submit --repo
   https://github.com/anna/engines --commit <40 знаков> --path engine`.

   Ревью читает код целиком: движок делает то, что о нём написано; зависимости явные; не
   трогает чужие данные на узле и не ходит в сеть без нужды. Отказ: поправить и подать
   новой версией.
   Код одобренной версии видит любой, кто вошёл на площадку (`looma engine code
   автор/движок`): прежде всего владельцы узлов, которые решают, принимать ли движок.
   Скажи автору об этом до подачи.
2. После одобрения модель переходит на версию с ревью и выходит в сеть:
   `looma model set solver --engine-version <N> --network`.
3. Цена модели: `looma model set solver --price call=1.5` (за вызов или единицу), у чата
   `--price in=… --price out=…`; публикация модели: `looma model publish solver`.
4. Другим авторам: `looma engine open solver`. Доля (`--fee`) идёт автору движка с чужих
   вызовов; со своих вызовов на своих узлах не берётся. Выплат пока нет.

## Правила

1. Код автора не трогай, пока не согласован план: что станет движком, какой у него API.
2. `engine try`, модель на своих узлах, пробные вызовы: можно делать в рамках принятого
   плана. Подача на ревью, открытие движка, публикация модели, выход в сеть, удаление:
   только по прямой просьбе.
3. Не говори «работает», пока `looma call` не вернул верный ответ.
4. Пределы площадки называй сразу: движок на одном узле, без секретов, пакет до 8 МБ,
   запрос до 32 МБ, задание до 24 часов, образ только на машинах площадки
   ([Договор движка](references/contract.md#пределы)).

## Частые причины

| Что видно | Причина и что делать |
|---|---|
| модель «не отвечает», реплики нет | своего узла нет на связи или движок на него не встаёт: `looma node list` |
| реплика падает сразу | `looma model logs`: ошибка импорта, нет пакета в requirements, нет файла в пакете |
| здоровье 503 долго | веса качаются или модель грузится: смотреть лог; закачку повторять при обрыве, `HF_HUB_DISABLE_XET=1` |
| `CUDA out of memory` | `vram_gib` в манифесте или `--set vram_gib=…` у модели меньше нужного; модель поменьше, половинная точность |
| `torch` не ставится или не видит карту | версия торча в requirements: убрать версию |
| 400 «у записи нет своего API» | модель создана как чат: `--set kind=api` или вызов через чат |
| 409 «версия без ревью работает только на ваших узлах» | модель в сети нельзя перевести на версию без ревью: `--own` или ревью |
| задание висит в очереди | реплика не поднялась: лог модели; задание ждёт до 6 часов |
| узел выключили посреди долгого задания | задание ждёт реплику до 6 часов и уходит заново с тем же `X-Looma-Job`; продолжит с места, только если служба пишет чекпойнты в `LOOMA_CACHE_DIR` и при старте задания ищет свой чекпойнт |
| нужны закрытые веса | движку секреты не передаются: веса только открытые; скажи автору до плана |
