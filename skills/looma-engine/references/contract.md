# Договор движка

Что площадка ждёт от движка и что даёт ему. Полная статья:
[engines.md](https://github.com/LoomaFloat/looma-kit/blob/main/docs/engines.md).

## Манифест `looma-engine.yaml`

```yaml
name: solver                     # строчная латиница, цифры, дефис; в каталоге anna/solver
title: Решатель
text: Одна-две фразы: что делает движок.
kinds: [api]                     # api (свой API), text (чат) или оба
package: solver                  # папка с кодом рядом с манифестом: только она едет на узел
command: [python, -m, solver.server]
requirements: requirements.txt   # или список строк; только пакеты, без параметров pip
weights: none                    # none или hf (модель называет репозиторий)
extensions: false
requires:
  device: [cuda]                 # cuda, mps, cpu
  vram_gib: 8                    # свободная память одной карты
  ram_gib: 16
  cuda: "12.1"                   # не ниже этой версии драйвера
fields:
  - key: steps
    label: Шагов
    type: int                    # text, int (min, max, step), bool, select (options)
    min: 1
    max: 100
    default: 30
    level: basic                 # basic или advanced
```

Пакет из своего файла в зависимостях: `имя @ https://…`. Ключи полей не совпадают с
занятыми площадкой (`engine`, `repo`, `kind`, `contours`, `own_node` и другие): ошибка
скажет, какой занят.

Движок-образ вместо `package`, `command`, `requirements` называет:

```yaml
image:
  dockerfile: Dockerfile
  port: 8000
  command: [python, -m, solver.server]   # не задан: ENTRYPOINT и CMD образа
requires:
  device: [cuda]
  ram_gib: 16                            # ещё и предел памяти службы
  cpus: 4
```

Образ слушает `0.0.0.0`, порт приходит и в `PORT`; работает только на машинах площадки, в
песочнице, сеть через прокси (порты 80 и 443). Ревью кода нет, версию одобряет сборка
образа (`looma engine submit`, ход в `looma engine show`).

## Что движок получает

| Переменная | Что в ней |
|---|---|
| `LOOMA_SERVE_PORT` | порт службы |
| `LOOMA_MODEL_ID` | имя модели в каталоге (`anna/solver`); чат возвращает его в `model` |
| `LOOMA_MODEL` | репозиторий весов, если модель его назвала (`weights: hf`) |
| `LOOMA_MODEL_REVISION` | закреплённый коммит этого репозитория (запись весов модели): передай его в `revision=` у `from_pretrained` и `snapshot_download`; пусто у моделей до записей весов |
| `LOOMA_ENGINE_OPTIONS` | поля рецепта модели одним JSON-объектом |
| `LOOMA_EXTENSIONS` | пакеты выбранных расширений JSON-списком |
| `HF_HOME` | общий кэш весов узла: скачанное один раз не качается заново |
| `LOOMA_CACHE_DIR` | постоянный каталог движка: переживает перезапуск реплики |
| `CUDA_VISIBLE_DEVICES` | карта, которую выделил узел |

Токена HuggingFace и секретов движку площадка не передаёт.

## Свой API (`kinds: [api]`)

Клиент зовёт `POST https://api.loomafloat.ru/v1/run/<автор>/<модель>/<путь>?<запрос>`,
служба получает `POST /<путь>?<запрос>`.

| Что | Как |
|---|---|
| до службы доходит | метод (GET, POST, PUT, PATCH, DELETE), путь, строка запроса, тело, заголовки; ключ и куки клиента не доходят |
| обратно уходит | статус, заголовки, тело по частям, как отдаёт служба; куки не ставить |
| размер запроса | до 32 МБ; больше: файлами к заданию |
| счёт | вызов стоит цену модели за единицу; число единиц служба называет `X-Looma-Units` (секунды, изображения, кадры); иначе одна |
| отказ | ответ 400 и выше клиенту не засчитывается |

## Долгие вычисления

Клиент шлёт тот же запрос с `Prefer: respond-async` (или `POST /v1/jobs` с `type: run`).
Площадка отвечает номером задания и доводит вызов сама.

- **Служба отвечает быстрее 10 минут:** ничего делать не нужно, ответ становится
  результатом задания.
- **Дольше:** служба сразу отвечает 202 и `Location: /jobs/<свой номер>`, считает в фоне.
  Площадка спрашивает `GET` этот адрес; пока считается, служба отвечает 202 (можно с
  `X-Looma-Progress: 40` и `Retry-After: 30`); первый другой ответ становится результатом.

| Что | Как |
|---|---|
| номер задания | `X-Looma-Job`: с запросом и каждым опросом. Повтор с тем же номером не должен начинать второе вычисление |
| повтор | реплика ушла или связь оборвалась: тот же запрос заново, до трёх раз |
| отмена | клиент снял задание: `DELETE` на адрес из `Location` |
| файлы клиента | `X-Looma-Files`: JSON, для каждого имени `url`, `bytes`, `content_type`, `filename`; ссылка живёт час |
| результат | до 256 МБ, хранится 7 дней; больше: служба кладёт в своё хранилище и отвечает ссылкой |
| сроки | ждёт реплику до 6 часов, считается до 24 часов |
| нагрузка | одна реплика получает до четырёх заданий сразу, остальные ждут в очереди площадки |

Промежуточный результат пиши в `LOOMA_CACHE_DIR`: после перезапуска реплики служба может
продолжить с места.

## Рецепт в запросе (`runs: true`)

Движок с `runs: true` принимает поля рецепта с каждым прогоном: `POST /v1/runs`, JSON
`{"recipe": поля, "inputs": входы}`. Поля уже проверены схемой `fields` и дополнены
значениями по умолчанию; не храни их между прогонами. Файлы приходят ссылками в
`X-Looma-Files`. Ответ любой, он и есть результат: сразу или 202 и `Location`; на
`DELETE` по нему бросай вычисление. Прогон до 10 минут; не уложился: ошибка, время и
доля не пишутся. Входы до 32 МБ, у вызывающего один идёт и до пяти ждут. Модель на
этом движке зовут своим адресом или чатом, поэтому служба отвечает на оба пути: поля
модели в `LOOMA_ENGINE_OPTIONS`, поля прогона в теле. Имена входов назови в `text`
манифеста. Весов у такого движка нет (`weights: none`). Прогоны других авторов идут
только на открытом движке. Образец: `engines/echo`, метод `run`.

## Чат (`kinds: [text]`)

`POST /v1/chat/completions` в формате OpenAI, целиком и потоком (`stream: true`, события
`data: …`, конец `data: [DONE]`). В ответе `usage` с `prompt_tokens` и
`completion_tokens`; в потоке `usage` в последнем событии перед `[DONE]`. Счёт в токенах.
Образец: [engines/llm](https://github.com/LoomaFloat/looma-kit/tree/main/engines/llm).

## Пределы

- Движок работает одним процессом на одном узле; реплик у модели может быть несколько,
  каждая на своём узле.
- Пакет: до 400 файлов и 8 МБ, файл до 1 МБ; архив папки для `engine try` до 16 МБ.
- Без ревью движок работает только на узлах автора (агент 0.1.66 и новее, владелец не
  запретил свой код без ревью). В сети и у других авторов только версия с ревью.
- Движок-образ работает только на машинах площадки.
- Секретов и токена HuggingFace у движка нет: открытые веса и открытые ссылки.
- Версия неизменна: модель закреплена за номером, новую версию модель берёт переходом.
