# Сервисы на Looma Float

Looma Float запускает сервисы авторов и даёт им модели своей сети. В CLI, API и
манифесте сервис называется app (`--app`, `/v1/apps`, `looma apps`). У сервиса два
окружения: **staging** (каждый новый релиз встаёт сюда сам) и **prod** (только
переводом). Адреса: `https://<имя>-staging.apps.loomafloat.ru` и
`https://<имя>.apps.loomafloat.ru`.

Когда сервис дописывают или меняют, держать в голове, зачем он на площадке: модели
вызывать из каталога сети (`looma models`, `gpu:` в манифесте, SDK `loomafloat`), а не
внешние API; сервису в каталоге не нужна своя регистрация, клиента передаёт витрина
(`access: clients`, заголовок `X-Looma-Client`); платные действия отмечать `charge`.

Работать через MCP-инструменты `looma_*`, если сервер подключён, иначе через CLI
`looma` в терминале (`looma status`, `looma deploy`, …). Действия у них одни и те же.
Вход пользователь делает сам: `looma login` откроет браузер на странице
console.loomafloat.ru/device. Ключ для CI выпускается в кабинете автора, раздел
«Подключение» (console.loomafloat.ru/connect).

## Правило: проверь перед записью, проверь после записи

1. **Перед** `deploy`, `promote`, `rollback`, `stop`, `secrets set` вызвать
   `looma_status` (`looma status`): что запущено, на каком релизе, есть ли ошибки. Перед
   `deploy` ещё и `looma validate`: за секунды и без релиза он находит ошибки манифеста
   и сверяет модели из `gpu:`.
2. **После** `deploy` проверить staging: `looma_check` (`looma check --env staging`).
   После `promote` или `rollback` проверить prod. Проверка идёт через API владельца и
   доходит до процесса даже при `access: clients`. Если ответ не 2xx, прочитать
   `looma_logs` нужного процесса и окружения и только потом делать выводы.
3. На prod переводить, когда staging проверен или пользователь просит явно.
   `destroy` только по прямой просьбе: уходят база, бакет и релизы.
4. Значения секретов не повторять в ответах и не писать в файлы проекта. Задавать их
   только через `looma_secrets_set`. Процессы видят новые значения после
   `looma_restart`.

## Манифест looma.yaml

```yaml
name: my-app                      # латиница, цифры, дефис
runtime: { kind: python, python: "3.12" }    # node: "22"; docker: { dockerfile: Dockerfile }
processes:
  web:    { cmd: "python app.py", port: 8080, min: 0, max: 1, idle_stop: 10m }  # слушать 0.0.0.0:$PORT
  worker: { cmd: "python worker.py", memory: 512Mi, cpu: 0.5 }
  nightly: { schedule: "0 3 * * *", cmd: "python nightly.py" }              # cron, UTC
data:
  postgres: { extensions: [vector] }   # → DATABASE_URL
  bucket: {}                           # → AWS_* и LOOMA_BUCKET (адресация S3 по пути)
gpu:
  chat: { model: Qwen3.8-Flash-Next-NVFP4 }    # имена как в /v1/models
secrets: [SENTRY_DSN]
events: [{ name: answer, title: Ответ, price: 2 }]   # события для charge, цена в рублях, до копеек
access: clients                        # только клиентам витрины (по умолчанию public)
listing:                               # карточка в каталоге
  title: Студия изображений
  summary: Что делает, одной строкой
  category: images     # assistants, images, video, text, code, data, business, education, fun, other
  tags: [изображения]
  icon: icon.png       # PNG, JPEG или WebP до 256 КБ (необязательно)
```

- С `min: 0` веб засыпает без запросов и просыпается первым запросом (до двух минут).
- На staging запускается только веб. Worker и cron работают только на prod.
- Процесс получает `LOOMA_APP_TOKEN`, `LOOMA_API_URL`, `LOOMA_APP_URL`,
  `LOOMA_ENVIRONMENT`, `LOOMA_RELEASE`, данные и секреты. В интернет он выходит через
  прокси.
- Сервис вызывает модели своим токеном через OpenAI-совместимый API, и только те, что
  в `gpu:`, иначе 403. В Python: `from loomafloat import Looma; Looma().chat(...)`.
  Какие модели есть и спят ли они, показывает `looma models` (`looma_models`).
- Свою модель в каталог добавляют, только когда моделей сети не хватает и пользователь
  просит об этом: `looma model` (`looma_model_*`). Начинать с настройки поверх модели
  сети (системный промпт, поля входа): ей не нужны свои видеокарты. Свои веса и адаптер
  держат свои реплики, их время идёт автору в расходы. Справка: docs/own-models.md.

## Маркетплейс

`looma_publish` (`looma publish`) отправляет на модерацию карточку из раздела `listing`
и цены из `events` релиза на **prod**. `looma_listing` показывает, в каталоге ли
карточка и почему отказ. Публиковать только по просьбе пользователя: карточку увидят
все. Чтобы поменять карточку или цены: правка `listing` или `events`, `deploy`,
`promote`, снова `publish`.

## Клиенты маркетплейса

Платформа называет клиента в запросе к сервису заголовком `X-Looma-Client`
(`client_of(headers)` в SDK). Это псевдоним без почты и имени. Модель для клиента
вызывается через `looma.for_client(client).chat(…)`, событие для учёта записывает
`looma.charge("answer", client)`. Имя события объявить в `events:` манифеста, иначе 400.
Без клиента (`None`) `charge` не вызывать. Цена события (`price`, в рублях) записывает
клиенту расход, автору доход. Действует цена одобренной карточки, то есть после
`looma publish` и модерации.

При `access: clients` посетителя без входа шлюз сам отправляет войти на витрине
(страница со ссылкой, для API ответ 401), до сервиса доходят только клиенты. Ставить,
когда вызов дорогой (видео, большие модели) или у каждого должны быть свои данные.

## Статистика

`looma_stats` (`looma stats`) показывает за заданное число дней запросы по каналам,
клиентов, события `charge`, вызовы моделей и себестоимость: каждый вызов записан по
прайсу на момент вызова, это те же суммы, что в «Доходе». Вызовы `looma dev` считаются
отдельно и в себестоимость не идут. Доход по сервисам (начислено, комиссия,
себестоимость моделей, итог) отдаёт `GET /v1/income?period=week|month|all`, а автор
видит его в кабинете автора (console.loomafloat.ru), раздел «Доход». Выплат пока нет:
заработок пользователю не обещать.

## Каналы

`channels:` в looma.yaml описывает, как клиент доберётся до сервиса кроме веба:
`api: { docs: /docs }` (по ключу клиента), `mcp: { tools: [{ name, description, path,
input }] }` (инструменты для ИИ-агентов: POST на `path`, ответ в JSON, текстом или
изображением). По описанию инструмента ИИ-агент решает, звать ли его, поэтому описание
писать конкретно.

## У себя: `looma dev`

`looma dev` в терминале запускает сервис на машине пользователя. Процесс долгий,
останавливается Ctrl+C; MCP-инструмента для него нет. Окружение как на платформе
(`LOOMA_ENVIRONMENT=dev`): база и бакет в Docker, модели настоящие, через dev-токен
сервиса (только из `gpu:`, 200 вызовов в сутки). Секреты пишутся строками в `.env`
проекта, в релиз этот файл не попадает. `looma dev run <процесс>` делает один запуск
(cron), `looma dev --docker` запускает в образе, как на платформе, `looma dev down`
останавливает. Проверить код до деплоя так дешевле, чем релизом.

## Перенос чужого проекта

Проект без `looma.yaml`, который надо перенести на площадку, ведёт skill `looma-port`:
оценка, план, переделка, деплой, отчёт.

## Шаблоны

`looma_init` / `looma init <папка> -t <шаблон>`: `hello`, `assistant` (чат на большой
модели), `image-studio` (генерация, правка и галерея в бакете, у каждого
клиента своя), `video-studio` (ролик по описанию: задание выполняется на платформе,
готовый ролик сохраняется в бакет, событие `video`). Шаблоны со SDK кладут его копию в
`loomafloat/`. После обновления CLI обновить копию командой `looma sdk` в папке проекта.

## Частые причины

- **Сборка не удалась.** Причина и хвост лога есть в результате `looma_deploy`
  (`log_tail`): зависимости в `requirements.txt` или `package.json`, ошибка манифеста.
- **403 от модели.** Модели нет в `gpu:` манифеста, или имя не совпадает с `/v1/models`
  (в `looma dev` после правки `gpu:` перезапустить `looma dev`).
- **429 `dev_quota_exceeded`** в `looma dev`. Дневная квота dev-вызовов сервиса выбрана,
  она обновится в 00:00 UTC. На staging и prod эта квота не действует.
- **503 на адресе.** Окружение остановлено или процесс падает: смотреть `looma_status`
  и `looma_logs`.
- **Процесс падает и перезапускается.** Смотреть `restarts` и `last_exit` в
  `looma_status`, сохранённый лог в `looma_logs`.
