# Свои модели без своего кода

Четыре вида своей модели, которым движок автора не нужен. Модель на движке автора ведёт
skill `looma-engine`. Полная справка:
[own-models.md](https://github.com/LoomaFloat/looma-kit/blob/main/docs/own-models.md).

Имя модели: `автор/имя`. Сначала модель видит и зовёт только автор; другим она доступна
после `looma model publish` и проверки площадки. Опубликованную модель зовут по её
имени ключом любой учётной записи площадки (ключ выпускается в кабинете, раздел
«Подключение») и из `gpu:` сервисов других авторов: так модель встраивают сторонние
разработчики.

## Настройка поверх модели сети

Своих видеокарт нет: настройка работает на репликах модели сети.

```bash
looma models                                   # выбрать основу
looma model add tone --base Qwen3.8-Flash-Next-NVFP4 --preset preset.json
looma call anna/tone "Проверка"                # пробный вызов
```

`preset.json` у текстовой модели: `system` (системный промпт), `template` (шаблон
сообщения с полями `{имя}`), `inputs` (поля входа: имя, подпись, тип), `params`
(температура, предел токенов). У изображений и видео: `prompt`, `inputs`, `params`.
Вызывают настройку как обычную модель, обычными сообщениями (`messages`, свободный
текст пользователя), а со своим входом полями: `looma.chat("anna/tone",
input={"text": "…"})`. Качество проверяй пробными вызовами (`looma call anna/tone "…"`)
на тех же примерах, на которых работал прежний поставщик, и показывай ответы автору.

Когда: вся «модель» сводится к промпту, шаблону и параметрам. Публикуется, как модель:
другие авторы ставят её в `gpu:` своих сервисов.

## Рецепты

Настройка поверх модели лежит у автора рецептом `автор/рецепт` с версиями: каждая
правка даёт версию (`looma recipe show имя`, MCP: `looma_recipe`). Рецепт бывает и полями
движка автора (`looma recipe add имя --engine автор/движок --set поле=значение`).

```bash
looma recipe                                # свои рецепты и открытые других авторов
looma recipe copy bob/tone                  # копия открытого рецепта: «основано на bob/tone»
looma recipe model tone --name tone-bot     # своя модель из своего рецепта
looma recipe publish tone                   # открыть другим авторам (проверка площадки)
```

Когда что предлагать:

- Автору нужна модель с промптом, похожим на чужой открытый рецепт: копия и модель из
  неё. Это быстрее, чем писать промпт с нуля. Скажи, что доли автору исходного рецепта
  нет и что в паспорте модели будет видно «основано на».
- Автор хочет, чтобы другие авторы брали его промпт и делали свои модели: открыть
  рецепт (`looma recipe publish`). Только по его слову: открытый рецепт видят целиком,
  включая системный промпт. Если промпт для автора ценен, предложи вместо этого
  опубликовать модель: её зовут по цене, а промпт вызывающим не виден.
- Автор хочет, чтобы его модель звали по цене: публикация модели (`looma model
  publish`), рецепт открывать не нужно.
- Чужой рецепт моделью без копии не заводится: сначала `looma recipe copy`.

Как рецепт связан с моделью: модель держит копию рецепта. `looma recipe add` (новая
версия) работающую модель не меняет; модель на новой версии заводится заново (`looma
recipe model`). `looma model set имя --preset` меняет модель и даёт рецепту версию.
Опубликованную модель так не правят: сначала `looma model unpublish` (на это время
чужие сервисы её не зовут), либо без простоя новая модель, публикация, перевод
сервисов. Похожий рецепт из своего: `looma recipe copy свой --name другой`; содержимое
в файл даёт `looma recipe show имя --json`. Отказ площадки по открытию: поправь,
`looma recipe add` (новая версия) и снова `looma recipe publish`. Паспорт модели
называет рецепт и версию, но содержимое закрытого рецепта тем, кто зовёт, не видно.

## Адаптер LoRA

```bash
looma model adapters                           # адаптеры проекта
looma model add legal --base Qwen/Qwen3-8B --adapter legal
```

Своя реплика: модель с вплавленным адаптером. Основа должна быть в каталоге.

## Свои веса на движке площадки

Веса модели лежат записью весов `автор/веса`: репозиторий HuggingFace целиком или
отдельные файлы safetensors, закреплённые коммитом. У каждой версии записи свой коммит.
Из одной записи собирают модели на разных движках, а паспорт модели показывает, чьи в
ней веса и какой коммит.

```bash
looma weights                                  # свои записи, открытые других авторов, свои адаптеры
looma weights add anna/qwen-legal              # завести запись: проверка и коммит   MCP: looma_weights
looma model check --weights anna/qwen-legal    # формат, размер, встанет ли в сети
looma model add qwen-legal --weights anna/qwen-legal
looma model set qwen-legal --always            # держать реплику всегда (иначе спит)
looma model set qwen-legal --price in=5 --price out=15   # рубли за 1M токенов
```

`--repo владелец/модель` вместо `--weights` тоже работает: запись весов заведётся сама,
закрепит последний коммит и появится в `looma weights` и в кабинете («Веса»). Своя
запись тех же весов не дублируется: закрепляется заново.

Запись зовётся `имя-автора/имя`, а не по владельцу репозитория: `looma weights add
Qwen/Qwen3-8B` у автора `anna` даст запись `anna/Qwen3-8B`. Имя берётся из имени
репозитория; другое задаёт `--name`. Команда печатает имя записи: дальше называй её.

Веса: открытый репозиторий HuggingFace без соглашения, safetensors, без своего кода
модели (`auto_map` в `config.json`), до 100 ГиБ (предел площадки; у раскладки diffusers
считается то, что поедет на узел). Названный `--revision` (коммит, ветка, метка)
площадка сверяет с HuggingFace: коммит, файлы и размер всегда берутся оттуда. Движки площадки: `torch` (по
умолчанию; большая модель делится на части по нескольким машинам), `vllm`, `diffusion`
(изображения и видео), `embed` (векторы и ре-ранк). Параметры движка: `--set
имя=значение`, список полей даёт кабинет («Модели» → «Своя модель»). torch, vLLM, embed
и движки авторов качают на узлы ровно закреплённый коммит; diffusion и FreeToken пока
качают свежую версию репозитория, паспорт модели это говорит.

**Когда что предлагать.**

- Свой файн-тюн автора, выложенный на HuggingFace: своя запись (`looma weights add`) и
  модель из неё.
- Веса, которые уже открыл другой автор (`looma weights`, «открытые веса авторов»):
  модель из его записи (`--weights bob/qwen-medical`). Автор весов виден в паспорте модели;
  доли с вызовов ему пока не идёт. Предлагай, когда автору нужны именно эти веса.
- Открытые веса известной модели (Qwen, Llama, FLUX): сначала посмотри модели сети
  (`looma models`). Если там есть та же модель, своя на тех же весах лишняя: она держит
  свои реплики, и время видеокарт идёт в расходы автора. Нужен только другой промпт или
  параметры: настройка поверх модели сети.
- Отдельный файл (LoRA, один чекпойнт) заводится записью с файлом
  (`looma weights add владелец/репозиторий/путь/файл.safetensors`, по желанию `--folder
  loras`). Модели на движке площадки нужен репозиторий целиком; запись с файлом для неё
  не годится.

**Открыть веса другим авторам:** `looma weights open qwen-legal`. Это сразу, без
проверки площадки: веса и так открыты на HuggingFace. Открывается запись целиком, со
всеми версиями, в том числе будущими. Открывай только по слову автора.
`looma weights close` закрывает запись; модели других авторов на ней работают дальше.

**Новая выкладка в репозиторий.** `looma weights add anna/qwen-legal` закрепит новый
коммит новой версией записи. Модели остаются на своей версии; новая модель берёт свежую.
Конкретную версию называют так: `--weights anna/qwen-legal@1`. Перевести работающую
модель на новую версию весов на месте пока нельзя: заводится новая модель (новое имя), её
проверяют пробными вызовами, сервис переводят на неё через staging, старую удаляют по
слову автора. У опубликованной модели новое имя проходит проверку площадки заново.

**Как выложить свои веса на HuggingFace,** если их там нет:

1. Репозиторий открытый (public) и без соглашения (gated): иначе узлы веса не скачают.
   Скажи автору, что выложенное увидят все.
2. Веса в safetensors: `model.save_pretrained(папка, safe_serialization=True)` у
   transformers или `safetensors.torch.save_file`. Файлы `.bin`, `.pt`, `.ckpt` площадка
   не берёт: это pickle, он исполняет код при чтении.
3. Без своего кода модели: `config.json` без `auto_map`. Архитектура должна быть
   знакома движку площадки, иначе нужен свой движок (skill `looma-engine`).
4. Выложить: `hf upload владелец/имя ./папка` (или `huggingface-cli upload`), затем
   `looma weights add владелец/имя`.

## Граф ComfyUI

Граф автора становится моделью на движке площадки `comfyui`: узлы ядра ComfyUI и узлы
наборов, одобренных площадкой (`looma comfy sets`, MCP: `looma_comfy_sets`). Своего кода и
своей видеокарты не нужно.

1. **Граф в API-формате.** В ComfyUI: Workflow → Export (API). Формат редактора (с
   `nodes` и `links`) не принимается.
2. **Разбор и черновик:**

   ```bash
   looma comfy inspect workflow_api.json --write portrait.comfy.yaml   # MCP: looma_comfy_inspect
   ```

   Прочитай «поправить». Наборы узлов, которыми граф пользуется, разбор назовёт сам
   («набор узлов: …») и впишет в `extensions` черновика; площадка закрепит их версию.
   Узлы, которых нет ни в ядре, ни в наборах (`unknown`): варианты в
   [Как распознать проект](recognize.md#граф-comfyui). Файлы не в safetensors (`.pth`,
   `.pt`, `.ckpt`, `.bin`): найти версию в safetensors; `.gguf` годится, если граф грузит
   его узлом набора GGUF.
3. **Веса.** У каждого файла из `weights` впиши `repo`: открытый репозиторий HuggingFace,
   где лежит ровно этот файл. Ищи по имени файла; у чекпойнтов и энкодеров есть
   перепаковки для ComfyUI (Comfy-Org, comfyanonymous, Kijai). Официальные репозитории
   часто закрыты соглашением (так у black-forest-labs, в том числе FLUX.1 schnell и его
   `ae.safetensors`): узел без токена такой файл не скачает, бери тот же файл из открытой
   перепаковки (сверь sha256 на странице файла). Закрытый репозиторий назовёт
   `looma model check`. Если файл лежит в подпапке
   репозитория, `file` пиши с путём, а имя, под которым его знает граф, в `name`. Своя LoRA
   автора: предложи выложить её в открытый репозиторий; без этого не получится. Скажи,
   что выложенное увидят все.
4. **Входы и выход.** Черновик угадывает `prompt`, `negative_prompt`, `seed`, `size`,
   `image`. С ними модель отвечает на общие запросы изображений и видео (`/v1/images`,
   витрина, чат). Любой другой вход (шаги, сила LoRA, второй текст) делает модель своим
   API (`/v1/run`, цена за вызов). Предложи автору выбор: со стандартными входами модель
   видна клиентам витрины, со своими она гибче для разработчиков.
5. **Прогон без модели.** Прежде чем заводить модель, прогони граф на площадке: он
   идёт на общих репликах, где ядро и все открытые наборы, и показывает, что граф
   здесь работает и что он выдаёт. Пока бесплатно.

   ```bash
   looma comfy run portrait.comfy.yaml --out result     # MCP: looma_comfy_run
   looma comfy runs run_…                               # MCP: looma_comfy_runs
   ```

   Файлы, которые граф грузит по имени (`LoadImage`), положи рядом с графом или назови
   `--file имя=путь`. Посмотри файлы в `result` сам или покажи автору; ошибку узла
   поправь в графе и прогони снова. Предлагай прогон, когда граф новый или поменялся,
   когда у автора нет своей видеокарты и когда отказ модели непонятен. Не нужен он,
   если граф уже работает моделью без изменений; модель заводится и без прогона.

   Прогон идёт на общей реплике: ядро и открытые наборы, карта на 20 ГиБ. Свой набор,
   который ещё не открыт (или без ревью), в прогоне недоступен: такой граф проверяй
   моделью. Узлов нет нигде (`unknown` в разборе): прогони граф без них, чтобы проверить
   остальное, а для них ищи замену (шаг 2). 10 минут считаются от начала счёта в
   ComfyUI; очередь и закачка весов в них не входят. Ход прогона: «в очереди», «качаю
   веса …», «узел N (тип), шаг k из n». Граф дольше 10 минут (длинное видео): для
   прогона уменьши кадры или разрешение, а полную длину проверяй моделью. Пределы:
   один прогон идёт и до пяти ждут, файлы хранятся 7 дней.

   Редактор ComfyUI. Человеку, который привык собирать граф мышью и у которого нет
   видеокарты, предложи редактор площадки: пункт «Редактор ComfyUI» в меню кабинета
   или `looma comfy editor` (настоящий интерфейс ComfyUI, запуск — прогон на площадке). Сам ты в
   браузер не ходишь, но каждый запуск в редакторе это прогон: его видно в `looma comfy
   runs`, и удачный становится черновиком модели по номеру, `looma comfy inspect run_…
   --write имя.comfy.yaml` (граф прогона ляжет рядом). Человек в кабинете делает то же
   кнопкой «Сделать моделью» в разделе «Редактор ComfyUI». Если автор уже работает в
   своём ComfyUI или отдал тебе граф файлом, редактор не нужен.

   Веса редактора. Если автор гоняет граф много раз или собирается в редакторе
   ComfyUI площадки, положи его файлы в веса редактора один раз, тогда прогон
   обходится без описания и `--weights` (и они же появятся в списках загрузчиков
   редактора):

   ```bash
   looma comfy weights                                   # MCP: looma_comfy_weights
   looma comfy weights add владелец/репозиторий/файл.safetensors --folder checkpoints
   looma comfy run workflow_api.json                     # веса из списков
   ```

   Папку бери из загрузчика графа (`CheckpointLoaderSimple` → `checkpoints`,
   `LoraLoader` → `loras`, `VAELoader` → `vae`, `UNETLoader` → `diffusion_models`,
   `CLIPLoader` → `text_encoders`). Сначала посмотри общий список площадки: файлы
   открытых моделей ComfyUI там уже есть, добавлять их не нужно. Файл в графе
   называется именем файла, как в списке; полное `владелец/репозиторий/файл` нужно,
   только когда одно имя у файлов из двух репозиториев (тогда и список показывает
   полные). Отказ «таких файлов 2» значит именно это: впиши в граф полное имя. Граф,
   который сам несёт ссылки на свои файлы на HuggingFace (шаблоны ComfyUI), при
   запуске в редакторе добавляет их в веса редактора сам. Путь в репозитории пишется целиком, с
   подпапками (`владелец/репозиторий/split_files/vae/файл.safetensors`). Прогон без
   `--weights` ищет в своих весах и в общем списке; с `--weights` или описанием смотрит
   только их. Модель весов из списков не берёт, но черновик `looma comfy inspect
   граф.json --write имя.comfy.yaml` заполняет `repo`, `file`, коммит и `name` сам для
   файлов из списков; проверь, что пустых `repo` не осталось.
6. **Проверка и добавление:**

   ```bash
   looma model check --from portrait.comfy.yaml        # MCP: looma_model_check с comfy
   looma model add portrait --from portrait.comfy.yaml # MCP: looma_model_add с comfy
   looma call anna/portrait --image "рыжий кот" --out cat.png              # род image
   looma call anna/clip --video "кот бежит по крыше" --out cat.gif          # род video
   looma call anna/portrait --data '{"prompt": "кот", "steps": 4}' --out cat.png   # род api
   ```

   Род video отвечает на `/v1/videos`; выход годится любой, который сохраняет узел
   сохранения видео ядра или набора (MP4, WebM, GIF, анимированный WebP). Цена за
   секунду считается по длине готового файла: её решает граф (кадры и частота), а не
   запрос клиента.

   Первый вызов долгий: реплика поднимается, ставит окружение и качает веса (минуты,
   у больших моделей десятки минут). Не отвечает: `looma model logs portrait`.
7. **Граф поменялся:** `looma model set portrait --from portrait.comfy.yaml`. Новая
   ревизия: реплики заменяются по одной, имя, цена и публикация остаются. Род
   опубликованной модели не меняется. Так же модель переходит на новую версию набора
   узлов: в `extensions` назови её номером (`автор/набор@3`) или без номера (свежая).
8. **Цена и публикация** такие же, как у любой своей модели (ниже); публикация только по
   просьбе автора.

Пределы: граф из узлов ядра и одобренных наборов; веса открытые и в safetensors (или в
формате, который читает набор, например `.gguf`), не больше предела своих весов (его
назовёт отказ `looma model check`; память карты сверх оценки по весам задаёт `vram_gib`
описания); граф
целиком на одной карте NVIDIA (драйвер CUDA 12.6+); модель с наборами узлов встаёт на
узлы с агентом 0.1.70 и новее; модель держит свои реплики, время карт идёт автору в
расходы (на своих узлах, `--own`, не записывается).

## Общее для своих моделей

| Что | Команда |
|---|---|
| описание | `looma model set имя --summary "…"` |
| цена | `--price call=…` (вызов со своим API), `in=…`, `out=…` (1M токенов), `image=…`, `second=…` (секунда видео); `--free` убирает |
| реплика всегда или сон | `--always`, `--sleep` |
| только свои узлы | `--own`; снова в сеть: `--network` |
| лог реплик | `looma model logs имя` |
| публикация | `looma model publish имя` (по просьбе автора), `unpublish` |
| удаление | `looma model delete имя --yes` (необратимо, по просьбе автора) |

Время карт под свои реплики идёт автору в расходы; на своих узлах не записывается. Из
сервиса модель зовут, объявив её в `gpu:` под полным именем: `chat: { model: anna/tone }`.
