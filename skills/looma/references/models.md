# Свои модели без своего кода

Четыре вида своей модели, которым движок автора не нужен. Модель на движке автора ведёт
skill `looma-engine`. Полная справка:
[own-models.md](https://github.com/LoomaFloat/looma-kit/blob/main/docs/own-models.md).

Имя модели: `автор/имя`. Сначала модель видит и зовёт только автор; другим она доступна
после `looma model publish` и проверки площадки. Опубликованную модель зовут по её
имени ключом любой учётной записи площадки (ключ выпускается в кабинете, раздел
«Подключение») и из `gpu:` сервисов других авторов: так модель встраивают сторонние
разработчики.

## Настройка поверх модели сети

Своих видеокарт нет: настройка работает на репликах модели сети.

```bash
looma models                                   # выбрать основу
looma model add tone --base Qwen3.8-Flash-Next-NVFP4 --preset preset.json
looma call anna/tone "Проверка"                # пробный вызов
```

`preset.json` у текстовой модели: `system` (системный промпт), `template` (шаблон
сообщения с полями `{имя}`), `inputs` (поля входа: имя, подпись, тип), `params`
(температура, предел токенов). У изображений и видео: `prompt`, `inputs`, `params`.
Вызывают настройку как обычную модель, обычными сообщениями (`messages`, свободный
текст пользователя), а со своим входом полями: `looma.chat("anna/tone",
input={"text": "…"})`. Качество проверяй пробными вызовами (`looma call anna/tone "…"`)
на тех же примерах, на которых работал прежний поставщик, и показывай ответы автору.

Когда: вся «модель» сводится к промпту, шаблону и параметрам. Публикуется, как модель:
другие авторы ставят её в `gpu:` своих сервисов.

## Адаптер LoRA

```bash
looma model adapters                           # адаптеры проекта
looma model add legal --base Qwen/Qwen3-8B --adapter legal
```

Своя реплика: модель с вплавленным адаптером. Основа должна быть в каталоге.

## Свои веса на движке площадки

```bash
looma model check --repo anna/qwen-legal       # формат, размер, встанет ли в сети
looma model add qwen-legal --repo anna/qwen-legal
looma model set qwen-legal --always            # держать реплику всегда (иначе спит)
looma model set qwen-legal --price in=5 --price out=15   # рубли за 1M токенов
```

Веса: открытый репозиторий HuggingFace, safetensors, без своего кода модели. Движки
площадки: `torch` (по умолчанию; большая модель делится на части по нескольким
машинам), `vllm`, `diffusion` (изображения и видео), `embed` (векторы и ре-ранк).
Параметры движка: `--set имя=значение`, список полей даёт кабинет («Модели» → «Своя
модель»).

## Граф ComfyUI

Граф автора становится моделью на движке площадки `comfyui`: узлы ядра ComfyUI и узлы
наборов, одобренных площадкой (`looma comfy sets`, MCP: `looma_comfy_sets`). Своего кода и
своей видеокарты не нужно.

1. **Граф в API-формате.** В ComfyUI: Workflow → Export (API). Формат редактора (с
   `nodes` и `links`) не принимается.
2. **Разбор и черновик:**

   ```bash
   looma comfy inspect workflow_api.json --write portrait.comfy.yaml   # MCP: looma_comfy_inspect
   ```

   Прочитай «поправить». Наборы узлов, которыми граф пользуется, разбор назовёт сам
   («набор узлов: …») и впишет в `extensions` черновика; площадка закрепит их версию.
   Узлы, которых нет ни в ядре, ни в наборах (`unknown`): варианты в
   [Как распознать проект](recognize.md#граф-comfyui). Файлы не в safetensors (`.pth`,
   `.pt`, `.ckpt`, `.bin`): найти версию в safetensors; `.gguf` годится, если граф грузит
   его узлом набора GGUF.
3. **Веса.** У каждого файла из `weights` впиши `repo`: открытый репозиторий HuggingFace,
   где лежит ровно этот файл. Ищи по имени файла; у чекпойнтов и энкодеров есть
   перепаковки для ComfyUI (Comfy-Org, comfyanonymous, Kijai). Официальные репозитории
   часто закрыты соглашением (так у black-forest-labs, в том числе FLUX.1 schnell и его
   `ae.safetensors`): узел без токена такой файл не скачает, бери тот же файл из открытой
   перепаковки (сверь sha256 на странице файла). Закрытый репозиторий назовёт
   `looma model check`. Если файл лежит в подпапке
   репозитория, `file` пиши с путём, а имя, под которым его знает граф, в `name`. Своя LoRA
   автора: предложи выложить её в открытый репозиторий; без этого не получится. Скажи,
   что выложенное увидят все.
4. **Входы и выход.** Черновик угадывает `prompt`, `negative_prompt`, `seed`, `size`,
   `image`. С ними модель отвечает на общие запросы изображений и видео (`/v1/images`,
   витрина, чат). Любой другой вход (шаги, сила LoRA, второй текст) делает модель своим
   API (`/v1/run`, цена за вызов). Предложи автору выбор: со стандартными входами модель
   видна клиентам витрины, со своими она гибче для разработчиков.
5. **Проверка и добавление:**

   ```bash
   looma model check --from portrait.comfy.yaml        # MCP: looma_model_check с comfy
   looma model add portrait --from portrait.comfy.yaml # MCP: looma_model_add с comfy
   looma call anna/portrait --image "рыжий кот" --out cat.png              # род image
   looma call anna/clip --video "кот бежит по крыше" --out cat.gif          # род video
   looma call anna/portrait --data '{"prompt": "кот", "steps": 4}' --out cat.png   # род api
   ```

   Род video отвечает на `/v1/videos`; выход годится любой, который сохраняет узел
   сохранения видео ядра или набора (MP4, WebM, GIF, анимированный WebP). Цена за
   секунду считается по длине готового файла: её решает граф (кадры и частота), а не
   запрос клиента.

   Первый вызов долгий: реплика поднимается, ставит окружение и качает веса (минуты,
   у больших моделей десятки минут). Не отвечает: `looma model logs portrait`.
6. **Граф поменялся:** `looma model set portrait --from portrait.comfy.yaml`. Новая
   ревизия: реплики заменяются по одной, имя, цена и публикация остаются. Род
   опубликованной модели не меняется. Так же модель переходит на новую версию набора
   узлов: в `extensions` назови её номером (`автор/набор@3`) или без номера (свежая).
7. **Цена и публикация** такие же, как у любой своей модели (ниже); публикация только по
   просьбе автора.

Пределы: граф из узлов ядра и одобренных наборов; веса открытые и в safetensors (или в
формате, который читает набор, например `.gguf`), не больше предела своих весов (его
назовёт отказ `looma model check`; память карты сверх оценки по весам задаёт `vram_gib`
описания); граф
целиком на одной карте NVIDIA (драйвер CUDA 12.6+); модель с наборами узлов встаёт на
узлы с агентом 0.1.70 и новее; модель держит свои реплики, время карт идёт автору в
расходы (на своих узлах, `--own`, не записывается).

## Общее для своих моделей

| Что | Команда |
|---|---|
| описание | `looma model set имя --summary "…"` |
| цена | `--price call=…` (вызов со своим API), `in=…`, `out=…` (1M токенов), `image=…`, `second=…` (секунда видео); `--free` убирает |
| реплика всегда или сон | `--always`, `--sleep` |
| только свои узлы | `--own`; снова в сеть: `--network` |
| лог реплик | `looma model logs имя` |
| публикация | `looma model publish имя` (по просьбе автора), `unpublish` |
| удаление | `looma model delete имя --yes` (необратимо, по просьбе автора) |

Время карт под свои реплики идёт автору в расходы; на своих узлах не записывается. Из
сервиса модель зовут, объявив её в `gpu:` под полным именем: `chat: { model: anna/tone }`.
