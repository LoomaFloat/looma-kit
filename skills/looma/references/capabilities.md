# Возможности площадки

Всё, что Looma Float может дать проекту автора, с командами. CLI и MCP делают одно и то
же: `looma model add` и `looma_model_add`, `looma node list` и `looma_node_list`.

## Сервис

Программа без видеокарты, описанная `looma.yaml`.

| Что | Как |
|---|---|
| процессы | `processes`: веб (порт из `$PORT`), фоновые, по расписанию (cron, UTC) |
| окружения | staging (каждый релиз) и prod (переводом): `looma deploy`, `looma promote`, `looma rollback` |
| данные | `data.postgres` (с расширениями, например `vector`) и `data.bucket` (S3) |
| модели | `gpu:` шаги с моделями каталога; вызов токеном сервиса через OpenAI-совместимый API или SDK `loomafloat` |
| свои модели и движки | тоже в `gpu:` под именем `автор/модель`; модель со своим API зовут через `/v1/run/автор/модель/путь` |
| секреты | `looma secrets set ИМЯ=значение` |
| у себя | `looma dev`: база и бакет в Docker, модели настоящие, 200 вызовов в сутки |
| каналы | `channels.api` (по ключу клиента), `channels.mcp` (инструменты для ИИ-агентов) |
| клиенты | `access: clients`: витрина пускает только вошедших, клиент приходит в `X-Looma-Client` |
| действия в каталоге человека | `account: [catalog.draft]` (и `catalog.publish`): с согласия человека сервис заводит его черновики весов, рецептов и моделей; ключ человека приходит в `X-Looma-Account-Key`, SDK `looma.for_person(ключ)`; человек отзывает в кабинете витрины («Доступы сервисов», `looma access`) |
| прогоны сервиса | `compute: { автор/движок: {} }`: сервис считает разово на движке с `runs: true` своим токеном (`looma.compute`), за свой счёт |
| цены | `events` с ценами и `charge` в коде; действует цена одобренной карточки |
| витрина | `listing` в манифесте и `looma publish` (модерация) |
| учёт | `looma stats`, `looma income` |

Шаблоны для нового сервиса: `looma init -t hello | assistant | image-studio | video-studio`.

## Модели сети

`looma models`: имя, тип (`text`, `image`, `video`, `embedding`, `rerank`), отвечает или
спит. Спящая модель просыпается первым вызовом (до 4 минут). Вызовы из сервиса идут на
клиента каталога и записываются автору как себестоимость.

## Свои модели

| Вид | Команда | Видеокарты | Когда |
|---|---|---|---|
| настройка поверх модели | `looma model add имя --base модель --preset файл.json` | не нужны | свой системный промпт, шаблон, поля входа, параметры |
| адаптер LoRA | `looma model add имя --base модель --adapter адаптер` | свои реплики | дообученный адаптер к модели сети |
| свои веса | `looma weights add владелец/модель`, `looma model add имя --weights автор/веса [--engine vllm]` (или `--repo владелец/модель`: запись весов заведётся сама) | свои реплики | запись весов закрепляет коммит, паспорт модели показывает владельца весов. Открытый репозиторий HuggingFace без соглашения, safetensors, архитектура, которую знает движок площадки. Движки: `torch` (большая модель делится на части по нескольким машинам), `vllm`, `diffusion` (изображения, видео), `embed` (векторы, ре-ранк). Проверка без запуска: `looma model check --weights …` |
| веса другого автора | `looma weights` (открытые веса авторов), `looma model add имя --weights bob/веса` | свои реплики | запись, которую автор весов открыл; владелец виден в паспорте, доли ему пока нет |
| разовое вычисление | `looma run автор/движок --set поле=значение --input имя=значение` (MCP `looma_run`) | общие исполнители движка, от нуля реплик | только движки с `runs: true`; рецепт проверяется как у модели; время карты и доля автора движка вызывающему; до 10 минут счёта |
| из рецепта | `looma recipe model рецепт --name имя` или `looma model add имя --recipe рецепт`; чужой открытый сначала `looma recipe copy автор/рецепт` | как у вида рецепта | рецепт: настройка поверх модели или поля движка автора, с версиями; копия помечена «основано на», доли автору исходного нет |
| граф ComfyUI | `looma comfy inspect граф.json --write имя.comfy.yaml`, прогон без модели `looma comfy run имя.comfy.yaml` (веса можно держать в весах редактора: `looma comfy weights add`), редактор в браузере `looma comfy editor`, `looma model add имя --from имя.comfy.yaml`; наборы узлов: `looma comfy sets` | свои реплики (прогон: общие реплики площадки, пока бесплатно) | граф из узлов ядра ComfyUI и одобренных наборов узлов (`extensions`) на движке `comfyui`; веса из открытых репозиториев HuggingFace в safetensors (`.gguf` с набором GGUF). Род `image` или `video` со стандартными входами, иначе своё API |
| набор узлов ComfyUI | `looma engine submit папка --extension` (`looma-extension.yaml` с `extends: comfyui`); до ревью `looma engine try папка` | ревью площадки | пакет набора до 2000 файлов и 64 МБ; узлы, которые он даёт графам, перечислены в манифесте; без `prestartup_script.py`, двоичных файлов, pickle и torch в зависимостях |
| на движке автора | `looma model add имя --engine автор/движок [--repo …] [--set поле=значение]` | свои реплики | любой код автора на карте |

Дальше одинаково: `looma model set` (описание, цена, реплики всегда или сон, узлы, версия
движка, поля движка), `looma model show`, `looma model logs` (лог реплик),
`looma model publish` (другие авторы зовут её по её цене; модерация), `looma call` (пробный
вызов). Время карт под свои реплики идёт автору в расходы, кроме реплик на своих узлах.

## Движки

Свой код на видеокарте. Подробно ведёт skill `looma-engine`.

| Что | Как |
|---|---|
| манифест | `looma-engine.yaml`: имя, `kinds`, пакет, команда, зависимости, `weights`, `requires`, `fields` |
| свой API | `kinds: [api]`: метод, путь, тело, заголовки уходят службе как есть; счёт за вызов или за единицы `X-Looma-Units` |
| чат | `kinds: [text]`: формат OpenAI, счёт в токенах, модель видна в общем чате |
| на своих узлах без ревью | `looma engine try <папка>`: версия одобрена сразу, работает только на узлах автора |
| в сети | `looma engine submit <папка>`: ревью площадки, подпись, узлы сети; по желанию вместо папки `--repo … --commit …` |
| чужой код | `looma engine code автор/движок`: код одобренной версии любого движка |
| образом | блок `image` и Dockerfile: любой язык, только машины площадки, ревью кода нет |
| доля | `--fee call=…` или `--fee in=… --fee out=…`: автору движка с чужих вызовов |
| другим авторам | `looma engine open` (после ревью) |
| расширения | `looma-extension.yaml`, `extensions: true` у движка |
| версии | модель закреплена за версией; переход `looma model set имя --engine-version N` |

## Долгие вычисления

Вызов модели со своим API, ответа на который клиент не ждёт: заголовок
`Prefer: respond-async` или `POST /v1/jobs` с `type: run`. Площадка отвечает номером
задания, доводит вызов до конца (повторы при потере реплики, до 24 часов), хранит ответ 7
дней. Служба отвечает сразу или 202 с `Location` и считает в фоне, сообщая ход
`X-Looma-Progress`. Большие входные данные идут файлами (`POST /v1/files`), конец задания
можно получить на `webhook_url`. CLI: `looma call модель --path … --async`, `looma job
номер --wait --out файл`.

## Узлы

| Что | Как |
|---|---|
| подключить | `looma node connect`: команда `docker run` с ключом для машины с NVIDIA |
| посмотреть | `looma node list`: на связи ли, карта, память, агент, что работает, какие движки встанут |
| держать модель на своих узлах | `looma model add … --own` или `looma model set имя --own` |
| на конкретном узле | `--node имя` у модели на движке автора |
| переименовать, отключить | `looma node rename`, `looma node disconnect --yes` |
| поделиться с сетью | только кабинет: «Узлы» → «Делюсь с сетью»; начисляется время карт |
| какой код принимает | только кабинет: «Узлы» → «Настройки» |

Своя модель на своём узле не платит за время карт, доля автора чужого движка со своих
вызовов не берётся. Пока ни один свой узел не на связи, модель только на своих узлах не
отвечает. Подробно: [Свои узлы](nodes.md).

## Деньги и учёт

Цены моделей сети показывает `looma models` (копейки за 1M токенов, изображение или
секунду видео): по ним считается себестоимость сервиса, от неё автор назначает цены
событий. Кто платит за вызов модели из сервиса: при `access: clients` и вызове
`for_client` клиент, иначе (открытый сервис, бот без клиентов витрины, фоновые задачи)
вызовы идут автору в себестоимость.

Клиент платит за события сервиса (`charge`) и за вызовы моделей по их цене. Автор
сервиса видит доход и себестоимость моделей, автор модели доход с её вызовов, автор движка
долю, владелец узла начисленное время карт: `looma income`, кабинет «Доход». Выплат пока
нет, заработок не обещать.

## Инструменты автора

| Где | Что |
|---|---|
| кабинет console.loomafloat.ru | всё, что ниже, плюс узлы с сетью, ключи API, профиль |
| CLI `looma` | сервисы, модели, движки, узлы, вызовы, задания, доход |
| MCP `looma mcp` | те же действия инструментами `looma_*` для ИИ-агента |

## Когда предлагать

| Возможность | Предлагать, когда | Не предлагать, когда |
|---|---|---|
| модели сети | проект зовёт внешний API или держит свой сервер модели, а в `looma models` есть модель того же типа | нужной модели в каталоге нет; автор прямо держится за конкретного поставщика |
| клиенты витрины | сервис идёт в каталог и у него своя регистрация | сервис не для каталога (`access: public`), вход нужен для чужой системы |
| цены событий | у сервиса есть понятные платные действия | автор делает сервис для себя или бесплатный |
| каналы API и MCP | у сервиса есть действия, полезные программам и агентам | сервис только страница без действий |
| настройка поверх модели | вся «модель» сводится к промпту и параметрам | нужен свой код или свои веса |
| адаптер LoRA | у автора есть адаптер к модели, которая есть в каталоге | основа адаптера не из каталога |
| свои веса | веса на HuggingFace, safetensors, архитектура знакома движкам площадки | нужен свой код вокруг модели: тогда движок; та же модель уже есть в сети, а нужен только промпт: тогда настройка |
| открыть свои веса авторам (`looma weights open`) | автор хочет, чтобы на его весах собирали модели другие | автор этого не просил: запись сначала видит только он |
| разовое вычисление (`looma run`) | проверить рецепт до модели; посчитать один раз; движок объявил `runs: true` | вызовы постоянные: модель (`looma model add` с тем же рецептом), её зовут по имени и по цене |
| прогоны из сервиса (`compute`) | сервис сам подбирает поля движка под каждый запрос (разные настройки, перебор), а движок объявил `runs: true` | поля одни и те же: модель на движке в `gpu:`, она дешевле в учёте и видна по имени; движка с `runs: true` нет |
| действия в каталоге человека (`account`) | сервис помогает человеку собрать свою модель: заводит черновик рецепта, запись весов или модель у него в каталоге (конструктор, мастер, импорт из другого сервиса) | сервису хватает своих данных; записи нужны самому сервису, а не человеку (тогда своя модель автора сервиса); сервис открыт не через витрину и человек не входит в Looma |
| открыть рецепт авторам (`looma recipe publish`) | автор хочет, чтобы его промпт или поля копировали другие | промпт для автора ценен: опубликуй модель, промпт вызывающим не виден |
| копия чужого рецепта (`looma recipe copy`) | нужна модель с почти таким же промптом, как в открытом рецепте | промпт нужен свой с нуля или нужна сама чужая модель: зови её по цене |
| граф ComfyUI | у автора граф ComfyUI из узлов ядра и наборов площадки, веса открыты или их можно выложить | узлов нет ни в ядре, ни в наборах: сначала замена узлов или модель каталога, затем свой набор на ревью, затем обёртка или движок-образ (порядок в `recognize.md`, «Граф ComfyUI»); закрытые веса |
| свой движок | свой код на карте, нестандартный пайплайн, расчёт, рендер, обучение, модель не в формате площадки | хватает модели каталога или своих весов на движке площадки |
| свой API у движка | вход и выход не чат: файлы, JSON, двоичные данные | обычный чат: тогда `kinds: [text]` |
| долгие вычисления | вызов идёт дольше минуты или ответ большой | ответ за секунды |
| движок-образ | не Python, системные библиотеки, готовый Docker-образ | движок должен работать на узлах автора: образ встаёт только на машины площадки |
| свой узел | у автора есть машина с NVIDIA и он хочет проверять движок или не платить за время карт | машины нет; Mac без NVIDIA для движков на CUDA |
| поделиться узлом | карта простаивает и автор согласен пускать на неё модели сети | на узле приватные данные автора; решать только автору |
| опубликовать модель | модель полезна другим и проверена вызовами; её зовут по ключу любой учётной записи площадки и из сервисов других авторов | модель держится только на своих узлах, а автор не готов держать узел на связи: пока он выключен, модель отвечает отказом. Модель на движке без ревью публикуется так же (через модерацию), но работает только на узлах автора |
| открыть движок, доля | движок общий: другие авторы соберут на нём свои модели | движок под один проект; версия без ревью |
| расширения | движок принимает плагины, а их пишут отдельно | одна программа без точек расширения |
| `looma dev` | сервис надо проверить до релиза | проект только движок |

## Пределы

Что площадка не умеет сейчас. Говорить до плана, не после правок.

- В процессе сервиса нет видеокарты; сборка сервиса идёт с 1 ГБ памяти и до 30 минут.
- Сервис говорит по HTTP: WebSocket, gRPC, TCP и UDP наружу не проходят; Streamlit и
  Jupyter не запускаются. Данные только Postgres и S3.
- Движок работает на одном узле: одну модель по нескольким машинам он не раскладывает
  (реплик может быть несколько, каждая на своём узле).
- Своя модель на движке площадки берёт веса только из открытого репозитория
  HuggingFace. Движку автора не передаются секреты и токен HuggingFace площадки: веса он
  тоже берёт из открытых репозиториев или по открытым ссылкам. Закрытые веса (свой стиль,
  платная LoRA) сейчас не спрятать: скажи автору прямо, что выложенные веса увидят все,
  и предложи держать в открытом доступе только то, что не жалко, или подождать
  секретов для движков.
- `looma check` делает запрос GET к вебу сервиса. POST с телом и файлами проверяют
  `curl` по адресу staging (при `access: public`) или в `looma dev`; при `access: clients`
  через API владельца клиента нет, и `charge` в такой проверке не записывается.
- Пакет движка до 400 файлов и 8 МБ (файл до 1 МБ, архив папки до 16 МБ): это код, веса
  движок скачивает сам.
- Запрос к модели со своим API до 32 МБ; ответ задания хранится до 256 МБ и 7 дней;
  задание ждёт реплику до 6 часов и считается до 24 часов.
- Движок без ревью работает только на узлах автора; в сети и у других авторов только
  после ревью. Движок-образ работает только на машинах площадки.
- Свой узел: Linux с NVIDIA, драйвер, Docker и NVIDIA Container Toolkit; код без ревью
  запускает агент 0.1.66 и новее (обновляется сам). Windows (WSL2) и Mac площадка как
  узлы для движков на CUDA не проверяла: так и скажи автору.
- Выплат пока нет: доход и начисления только учитываются.
