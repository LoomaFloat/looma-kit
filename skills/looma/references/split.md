# Сервис и движок вместе

Проект, где веб и вычисление на видеокарте живут вместе (FastAPI и `diffusers` в одном
процессе, бот и своя модель, страница и рендер), на площадке делится на две части:

- **сервис** (`looma.yaml`): страницы, API, клиенты, база, бакет, цены; без видеокарты;
- **движок** (`looma-engine.yaml`) и **модель** на нём: код на карте, отвечает по API.

Сервис зовёт модель так же, как модели сети: объявляет её в `gpu:` и вызывает токеном
сервиса. Площадка сама поднимает реплики движка на узлах, будит спящую модель и считает
вызовы.

## Как разделить

1. Найди границу: функцию или класс, который получает вход (промпт, файл, параметры) и
   возвращает результат, считая на карте. Это и есть вызов движка.
2. Предложи раскладку папок и дождись согласия:

   ```
   проект/
     service/            looma.yaml, веб, база, шаблоны
     engine/             looma-engine.yaml, пакет движка, requirements.txt
   ```

   Если переносить код нельзя (автор держит один репозиторий для себя), движок может
   лежать в подпапке рядом с вебом: в пакет движка едет только папка `package` из его
   манифеста, в релиз сервиса только то, что не в `.loomaignore`.
3. Движок: skill `looma-engine` (контракт, свой API, долгие вычисления, проверка на своём
   узле). Вход и выход выбирай так, чтобы веб передавал данные, а не объекты Python:
   JSON с параметрами, файлы байтами или ссылками.
4. Модель на движке: `looma model add имя --engine автор/движок [--repo …]`.
5. Сервис: skill `looma-port`. Вызов модели вместо прямого кода на карте; тяжёлые пакеты
   (`torch`, `diffusers`) из зависимостей сервиса убрать.

## Как сервис зовёт свою модель

```yaml
# looma.yaml сервиса
gpu:
  render: { model: anna/render }       # модель на движке автора
```

Модель со своим API (`kinds: [api]`):

```python
from loomafloat import Looma, client_of

looma = Looma()                                      # токен сервиса из окружения
answer = looma.run("anna/render", "/frames", body={"scene": scene_id, "frames": 24})
png = answer.content                                 # ответ службы как есть

# Долгое вычисление: ответить клиенту сразу, результат забрать позже.
job = looma.for_client(client_of(request.headers)).run(
    "anna/render", "/video", body={"scene": scene_id}, wait=False)
save_job_id(job.id)                                  # в базу: процесс может уснуть
...
job = looma.job(saved_id)
if job.status == "succeeded":
    video = job.content()
```

Двоичное тело (изображение, архив) уходит как есть: `looma.run("anna/render", "/sketch",
body=open("sketch.png", "rb").read(), headers={"Content-Type": "image/png"})`. Больше
32 МБ: файлом задания (`POST /v1/files`, затем `POST /v1/jobs` с `files`).

Без SDK: `POST $LOOMA_API_URL/run/anna/render/frames` с заголовком
`Authorization: Bearer $LOOMA_APP_TOKEN`; для задания ещё `Prefer: respond-async`, затем
`GET $LOOMA_API_URL/jobs/<номер>` и `/jobs/<номер>/content`.

Модель-чат (`kinds: [text]`): как любая модель сети, `looma.chat("anna/tutor", …)` или
OpenAI-совместимый клиент с `base_url=$LOOMA_API_URL`.

## Порядок работ

1. Движок: написать, проверить у себя, `looma engine try`, модель на нём, `looma call`.
2. Сервис: `gpu:` с моделью, вызов в коде, `looma validate`, `looma dev` или
   `looma deploy` на staging, `looma check`.
3. Сквозная проверка: запрос к сервису, который доходит до движка; лог модели
   (`looma model logs`), если что-то не так.
4. По просьбе автора: prod, цены, публикация сервиса. Если сервис идёт клиентам витрины,
   а модель стоит на движке без ревью, она работает только на узлах автора: пока его узел
   не на связи, сервис получит отказ модели. Скажи об этом автору до публикации и
   предложи ревью движка, чтобы модель держалась и в сети. Обёртку вокруг ComfyUI ревью
   не пройдёт: для неё предложи движок-образ с ComfyUI или запасной путь в сервисе
   ([Граф ComfyUI](recognize.md#граф-comfyui)).
   Карточку сервиса всё равно проверяет модерация.
5. Отчёт `LOOMA_PORT.md` в корне проекта описывает обе части: сервис (адреса, секреты,
   как выпускать) и движок с моделью (имя, версия, на каких узлах, как вызвать, как
   обновить: `looma engine try` и `looma model set … --engine-version latest`).
