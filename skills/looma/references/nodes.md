# Свои узлы

Узел: машина автора с видеокартой, подключённая к площадке. Свой узел работает только на
автора, пока тот не решит поделиться им с сетью.

Что даёт свой узел:

- свои модели на нём не платят за время карт; со своих вызовов не берётся доля автора
  чужого движка;
- свой движок встаёт на него без ревью (`looma engine try`): так его проверяют до подачи
  на ревью, а для личных вычислений ревью не нужно вовсе;
- если поделиться им с сетью, на нём работают модели каталога, а автору начисляется время
  карт (выплат пока нет).

## Что нужно машине

- Linux с видеокартой NVIDIA и драйвером (`nvidia-smi` работает);
- Docker и NVIDIA Container Toolkit (`docker run --rm --gpus all ubuntu nvidia-smi`
  показывает карту);
- выход в интернет: агент сам соединяется с площадкой, входящие порты не нужны.

Проверить машину перед подключением, если у тебя есть к ней доступ:

```bash
nvidia-smi && docker run --rm --gpus all ubuntu nvidia-smi
```

## Подключить

```bash
looma node connect --label "Домашний ПК"     # MCP: looma_node_connect
```

Ответ: имя узла и команда `docker run … gihpee/looma-agent:1.0.0 --key … --node-id …`. В
команде ключ: он показывается один раз. Не пересказывай его в ответах и не пиши в файлы
проекта. Варианты:

- автор запускает команду сам на своей машине: дай её одним блоком;
- машина та же, где работаешь ты, или автор дал доступ по SSH и попросил: запусти сам.

Через минуту узел на связи:

```bash
looma node list                               # MCP: looma_node_list
```

В строке узла: на связи ли, карта и свободная память, версия агента, делится ли с сетью,
что на нём работает и какие движки на него встанут, а какие нет и почему.

## Если узел не появился

| Что видно | Что делать |
|---|---|
| узел «ждёт подключения» | команду не запускали или контейнер упал: `docker ps -a`, `docker logs <контейнер>` на машине |
| в логе агента `orchestrator refused this node` | ключ отозван или команда скопирована не целиком: `looma node connect` даст новую |
| на связи, «задач не берёт» | причина в строке узла: нет карты, мало места, агент обновляется (подождать) |
| движок «не встанет» | причина рядом: мало памяти карты, нет нужного `device`, агент старше 0.1.66, владелец запретил свой код без ревью |

## Модель на своём узле

```bash
looma model add parrot --engine anna/echo --own        # любой свой узел
looma model add parrot --engine anna/echo --node home-1 # только этот узел
looma model set parrot --own                           # уже заведённую — на свои узлы
looma model set parrot --network                       # снова и в сеть (если код прошёл ревью)
```

Пока ни один свой узел не на связи, модель только на своих узлах не отвечает: на узлы
сети она не уходит.

## Только в кабинете

Две настройки меняет только владелец учётной записи в кабинете автора
(console.loomafloat.ru/nodes), ключом CLI их не поменять:

- **«Делюсь с сетью»**: на узел встают модели каталога, автору начисляется время карт.
  Когда забирает узел обратно, чужие модели снимаются сразу. Предлагай, когда карта
  простаивает; решает автор.
- **«Настройки» узла**: принимать ли проверенный код других авторов (по умолчанию да,
  можно список движков) и свой код без ревью (по умолчанию да). На машине владелец может
  запретить свой код без ревью и сам: `-e LOOMA_OWN_CODE=0` в команде агента.

## Отключить

```bash
looma node rename home-1 --label "Стенд"
looma node disconnect home-1 --yes      # по просьбе автора: ключ отзывается, работа снимается
looma node forget home-1                # убрать из списка узел, которого нет на связи
```
