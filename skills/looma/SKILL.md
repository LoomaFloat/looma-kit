# Looma Float: проект автора от кода до каталога

Looma Float: маркетплейс ИИ-сервисов на сети видеокарт. Автор приносит код, площадка даёт
ему хостинг, модели, видеокарты, клиентов и учёт. Этот skill ведёт автора целиком: ты
разбираешься, что перед тобой, предлагаешь, что площадка может дать именно этому проекту,
договариваешься с автором и делаешь всё сам инструментами `looma_*` (или CLI `looma`).

Начинай отсюда, когда автор приносит проект, идею или вопрос «как это сделать на Looma».
Уже идущую работу ведут узкие skills: `looma-port` (перенос веб-проекта в сервис),
`looma-apps` (жизнь сервиса: релизы, логи, секреты, публикация), `looma-engine` (свой код на
видеокарте: движок, модель на нём, проверка на своих узлах).

## Карта площадки

Пять понятий. Всё, что умеет площадка, собирается из них.

| Что | Что это | Где описывается |
|---|---|---|
| **Сервис** (app) | программа без видеокарты: веб, API, MCP-инструменты, фоновые процессы, cron. Postgres, S3-бакет, домен с TLS, staging и prod | `looma.yaml` |
| **Модель** | то, что считает на видеокартах и отвечает по API. Модели сети (их держит площадка) и свои модели автора | каталог: `looma models`, `looma model` |
| **Движок** | программа автора, которая работает на видеокарте и отвечает на запросы: своя модель, свой пайплайн, любое вычисление | `looma-engine.yaml` |
| **Узел** | машина с видеокартой в сети. Свой узел автора работает на него; поделиться им с сетью автор может сам | `looma node`, кабинет «Узлы» |
| **Клиент** | человек или программа, которые пользуются сервисом или моделью через витрину, API или MCP | витрина, `X-Looma-Client` |

Как они связаны:

```
клиент → витрина / API / MCP → сервис ──gpu:──→ модель ──рецепт──→ движок ──реплики──→ узлы
```

Свои модели автора бывают пяти видов, от лёгкого к тяжёлому:

1. **Настройка поверх модели сети** (`--base … --preset`): системный промпт, шаблон, поля
   входа, параметры. Своих видеокарт не нужно.
2. **Модель сети с адаптером LoRA** (`--base … --adapter`).
3. **Свои веса на движке площадки** (`--repo владелец/модель`): torch, vLLM, diffusion,
   эмбеддинги. Веса с HuggingFace, safetensors.
4. **Граф ComfyUI** (`--from описание.comfy.yaml`): граф автора из узлов ядра и наборов
   узлов площадки (`looma comfy sets`) на движке `comfyui`, без своего кода.
5. **Модель на движке автора** (`--engine автор/движок`): любой код автора на карте.

Движок бывает процессом на Python (по умолчанию; на своих узлах без ревью, в сети после
ревью) или образом с Dockerfile (любой язык, только на машинах площадки, ревью кода нет).
Отвечает движок либо своим API (`kinds: [api]`: любые адреса, любые данные, долгие
вычисления заданием), либо как чат OpenAI (`kinds: [text]`).

Подробно, с командами: [Возможности площадки](references/capabilities.md).

## Шаг 1. Понять, что перед тобой

Два источника: что автор хочет получить и что лежит в коде.

**Намерение.** Если оно не названо, спроси одним вопросом с вариантами: сервис для людей
(страница, бот), API для разработчиков, инструменты для ИИ-агентов, модель или движок для
других авторов, вычисление для себя, загрузить простаивающую видеокарту. Ответ меняет
путь: одно и то же вычисление для себя идёт на свой узел, для клиентов идёт в каталог.

**Код.** Запусти оценку и прочитай находки по указанным строкам:

```bash
looma assess <папка> --json        # MCP: looma_assess
```

В ответе `shape`: `service` (веб без своих вычислений на карте), `engine` (вычисление на
карте без веба), `both` (то и другое), `unknown` (скрипт, библиотека, бот без веба).
Оценка ищет приметы по тексту, решение за тобой. Приметы и что они значат:
[Как распознать проект](references/recognize.md).

Сформулируй для себя и потом для автора: что из проекта станет сервисом, что моделью,
что движком, а что не нужно вовсе (свой сервер Ollama, своя регистрация, свои веса в
репозитории).

## Шаг 2. Подобрать варианты

Площадка может дать проекту много. Предлагай то, на что есть повод в коде или в
намерении автора, и не предлагай остальное: список возможностей не нужен автору целиком.
Каждое предложение: что это даст ему, сколько работы, что решает он сам.

Самые частые поводы:

| Повод в коде или в словах автора | Что предложить |
|---|---|
| вызовы OpenAI, Anthropic, Gemini, локального Ollama | модели сети того же типа (`looma models`): без стороннего ключа, себестоимость в кабинете |
| своя регистрация и вход у сервиса для каталога | клиентов витрины: `access: clients`, данные по `X-Looma-Client` |
| действия, за которые можно брать деньги | цены событий: `events` и `charge`; цены называет автор |
| HTTP API у сервиса или его хотят звать из программ | канал API (`channels.api`) и инструменты для ИИ-агентов (`channels.mcp`) |
| API к своей модели (весам, графу ComfyUI) для разработчиков, без своей страницы и логики | опубликовать модель: её зовут ключом любой учётной записи площадки по общим адресам или `/v1/run`; сервис не нужен |
| промпт-обёртка над чатом, «бот с характером» | настройку поверх модели сети: без своих карт, публикуется как модель |
| свой файн-тюн LoRA | модель сети с адаптером |
| свои веса на HuggingFace в формате площадки | свою модель на движке площадки (`--repo`) |
| свой код на карте: пайплайн, нестандартная модель, расчёт, рендер, обучение | свой движок: на своих узлах без ревью, в сети после ревью |
| граф ComfyUI, `custom_nodes/` | `looma comfy inspect`; граф из узлов ядра и наборов площадки становится своей моделью на движке `comfyui` (`--from описание`, наборы в `extensions`); узлов нет нигде или свой набор: [Граф ComfyUI](references/recognize.md#граф-comfyui) |
| вычисление дольше минуты | долгие вычисления заданием: `Prefer: respond-async`, ответ 202 и `Location` |
| у автора есть видеокарта | свой узел: свои модели на нём не платят за время карт, движок встаёт без ревью |
| видеокарта простаивает | поделиться узлом с сетью: начисляется время карт (решает автор в кабинете) |
| модель или движок полезны другим | опубликовать модель; открыть движок авторам с долей с чужих вызовов |
| движок принимает плагины, которые пишут отдельно | расширения движка |

Полный список с условиями «когда уместно» и «когда нет»: [Возможности
площадки](references/capabilities.md#когда-предлагать).

## Шаг 3. План автору

Коротко и по делу, до правок кода:

1. **Что это:** одной-двумя фразами, из каких частей станет проект на площадке.
2. **Варианты:** два-четыре подходящих, с рекомендацией и причиной. Если проект можно
   сделать и проще (модель каталога вместо своего движка), так и скажи.
3. **Что сделаю я:** по шагам, какие файлы появятся или поменяются.
4. **Что решаете вы:** цены, публикация, делиться ли узлом, переносить ли данные.

Дождись согласия. Код автора не трогай, пока план не принят.

## Шаг 4. Пройти путь

| Часть проекта | Как вести |
|---|---|
| веб-проект → сервис | skill `looma-port`: оценка, переделка под `looma.yaml`, staging, проверка, отчёт |
| работающий сервис | skill `looma-apps`: релизы, логи, откат, секреты, статистика, публикация |
| свой код на карте → движок | skill `looma-engine`: оформить движок, проверить у себя, поставить на свой узел, модель, вызов |
| своя модель без своего кода | [Свои модели](references/models.md): настройка, адаптер, свои веса |
| узлы | [Свои узлы](references/nodes.md): подключить, проверить, что встанет |
| сервис и движок вместе | [Сервис и движок вместе](references/split.md): разделить репозиторий и связать |

После каждого шага проверяй результат сам: `looma_check` для сервиса, `looma_call` для
модели, `looma_model_logs`, если модель не отвечает. Не говори «готово», пока не увидел
ответ.

## Правила

1. **Проверь перед записью и после.** Перед изменением смотри состояние (`looma_status`,
   `looma_model_list`, `looma_node_list`), после изменения проверяй вызовом.
2. **Только по прямой просьбе автора:** перевод на prod (`promote`), публикация сервиса,
   модели или карточки, подача движка на ревью, открытие движка другим авторам,
   отключение узла, удаление сервиса или модели. Предлагать их можно и нужно, делать
   только после «да».
3. **Только сам автор, в кабинете:** поделиться узлом с сетью, выбрать, чей код узел
   принимает. Ключом CLI это не делается: объясни, что это значит, и дай ссылку на
   console.loomafloat.ru/nodes.
4. **Секреты и ключи не пересказывай.** Секреты задаются `looma_secrets_set`; команду
   подключения узла с ключом показывай автору один раз или запускай сам на его машине,
   если он попросил.
5. **Заработок не обещай.** Цены записывают клиенту расход, автору доход, но выплат пока
   нет: это учёт.
6. **Говори о пределах прямо.** Если площадка чего-то не умеет, скажи это до плана, а не
   после правок: [Чего площадка не умеет](references/capabilities.md#пределы).
7. **Минимальные правки.** Переделывай то, что мешает площадке, и то, что автор принял в
   плане. Код, который работает, не переписывай.

## Готовность

```bash
looma --version          # CLI есть? Нет: uv tool install "git+https://github.com/LoomaFloat/looma-kit"
looma whoami             # вход выполнен? Нет: `looma login` делает сам автор в браузере
looma model name         # имя автора: с него начинаются имена моделей и движков
```

Имя автора задаётся один раз и не меняется: предложи вариант, но задавай только с
согласия автора.
