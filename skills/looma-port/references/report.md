# Шаблон отчёта LOOMA_PORT.md

Отчёт пишется в корень проекта после переноса (или после оценки, если перенос
невозможен). Коротко и по делу: его читает автор проекта, а не агент.

```markdown
# Перенос на Looma

**Итог:** <работает на staging | работает с оговорками | не перенесён: почему>
**Staging:** https://<имя>-staging.apps.loomafloat.ru/
**Prod:** <ещё нет — `looma promote` | https://<имя>.apps.loomafloat.ru/>

## Что изменено

| Файл | Что и зачем |
|---|---|
| looma.yaml | манифест: веб, база, бакет, модели |
| app/db.py | SQLite → Postgres (DATABASE_URL): диск площадки временный |
| … | … |

## Модели

| Шаг в gpu: | Модель | Вместо чего |
|---|---|---|
| chat | <имя> | gpt-4o-mini через OpenAI API |

## Что не перенесено

- <что, почему, что можно сделать>

## Секреты

Задать перед запуском (значения — только у вас):
`looma secrets set ИМЯ=…` для: <ИМЕНА>

## Как обновлять

1. Правка кода → `looma validate` → `looma deploy` (встанет на staging).
2. Проверка: `looma check --env staging`, при ошибке — `looma logs --env staging`.
3. На prod: `looma promote`. Откат: `looma rollback`.
4. Карточка в каталоге маркетплейса: раздел `listing` в looma.yaml → `looma publish`.

## Проверено

- <путь>: <код ответа, что проверяли>
```

Если перенос невозможен — те же разделы «Итог» и «Что не перенесено» с блокерами из
оценки и тем, что должно появиться на площадке, чтобы перенос стал возможен.
