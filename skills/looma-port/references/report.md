# Шаблон отчёта LOOMA_PORT.md

Отчёт пишется в корень проекта после переноса или после оценки, если перенос
невозможен. Писать коротко и по делу, обращаться к автору на «вы»: отчёт читает автор
проекта, а не ИИ-агент.

```markdown
# Перенос на Looma Float

**Итог:** <работает на staging | работает с оговорками | не перенесён: почему>
**Staging:** https://<имя>-staging.apps.loomafloat.ru/
**Prod:** <ещё нет, перевод командой `looma promote` | https://<имя>.apps.loomafloat.ru/>

## Что изменено

| Файл | Что и зачем |
|---|---|
| looma.yaml | манифест: веб, база, бакет, модели |
| app/db.py | SQLite → Postgres (DATABASE_URL): диск площадки временный |
| … | … |

## Модели

| Шаг в gpu: | Модель | Вместо чего |
|---|---|---|
| chat | <имя> | gpt-4o-mini через OpenAI API |

## Что не перенесено

- <что, почему, что можно сделать>

## Секреты

Задайте перед запуском, значения знаете только вы:
`looma secrets set ИМЯ=…` для: <ИМЕНА>

## Как обновлять

1. Измените код, затем выполните `looma validate` и `looma deploy`: релиз встанет на staging.
2. Проверьте staging: `looma check --env staging`. При ошибке смотрите `looma logs --env staging`.
3. Переведите релиз на prod: `looma promote`. Откат: `looma rollback`.
4. Карточка в каталоге: заполните раздел `listing` и цены в `events` в looma.yaml, затем
   `looma publish` отправит карточку и цены на модерацию.

## Проверено

- <путь>: <код ответа, что проверяли>
```

Если перенос невозможен, в отчёте остаются разделы «Итог» и «Что не перенесено»: блокеры
из оценки и то, что должно появиться на площадке, чтобы перенос стал возможен.
