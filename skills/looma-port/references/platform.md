# Площадка Looma: что даёт и чего не умеет

Сверено с кодом платформы. Числа — действующие пределы; если площадка их поменяет,
`looma validate` и сборка скажут об этом раньше этого файла.

## Что даёт

| Что | Как получить |
|---|---|
| Сборка Python и Node.js | `runtime: { kind: python }` или `{ kind: node }`: Dockerfile пишет платформа |
| Любой другой стек | свой Dockerfile: `runtime: { kind: docker, dockerfile: Dockerfile }` |
| Веб, фоновые процессы, задачи по расписанию | `processes:` в манифесте |
| Postgres | `data.postgres`, строка подключения — `DATABASE_URL` |
| S3-бакет | `data.bucket`, доступы — `AWS_*`, имя — `LOOMA_BUCKET` |
| Домен и TLS | `https://<имя>.apps.loomafloat.ru`, staging — `https://<имя>-staging.apps.loomafloat.ru` |
| Модели ИИ сети Looma | `gpu:` в манифесте, вызовы — токеном `LOOMA_APP_TOKEN` на `LOOMA_API_URL` |
| Секреты | `looma secrets set ИМЯ=значение`, в процессе — переменная окружения |
| Выход в интернет | HTTP и HTTPS через прокси (переменные `HTTP_PROXY`, `HTTPS_PROXY`) |

## Пределы

| Что | Предел |
|---|---|
| Архив исходников | до 100 МБ сжатым, до 1 ГБ распакованным, до 20 000 файлов |
| Сборка | 1 ядро, 1 ГБ памяти, до 30 минут; образ под amd64 |
| Процесс | 0,1–8 ядер (по умолчанию 0,5), 64Mi–32Gi памяти (по умолчанию 512Mi), до 10 экземпляров |
| Веб-процесс | один на приложение, порт 1024–65535 |
| Запрос к приложению | только HTTP, тело до 32 МБ; потоковые ответы (SSE, chunked) работают |
| Выход наружу | только порты 80 и 443, только публичные адреса |
| `/dev/shm` | 64 МБ |

## Чего нет — и что с этим делать

| Нет | Что делать |
|---|---|
| **GPU в процессе** | модели — из каталога Looma по API ([models.md](models.md)); обучение здесь не делают |
| **WebSocket** (шлюз отвечает 501) | стрим ответа — SSE; уведомления — SSE или опрос; Streamlit, Jupyter — переписать на обычный веб |
| **Протоколы кроме HTTP** (gRPC, свой TCP/UDP) | только HTTP API |
| **Постоянный диск** | диск процесса стирается при перезапуске, сне и новом релизе: данные — в Postgres и бакет ([data.md](data.md)) |
| **Redis, MongoDB, MySQL, брокеры, поисковые движки** | только Postgres и S3; замены — в [data.md](data.md) |
| **Внешние базы и сервисы на портах кроме 80/443** (Atlas 27017, Redis 6379, SMTP 587) | HTTPS-вариант сервиса или замена |
| **Привилегии** (Docker внутри, монтирование, `privileged`) | не обойти |
| **Браузер без окна** (Chromium) | скорее всего не запустится (песочница gVisor, `/dev/shm` 64 МБ): проверять на staging или внешний сервис рендеринга |

## Как живёт процесс

- **Песочница gVisor.** Файловая система — копия образа: писать можно, но всё
  записанное пропадёт при перезапуске. Временные файлы в `/tmp` — нормально.
- **Сон.** Веб с `min: 0` засыпает после `idle_stop` без запросов (по умолчанию 5 минут)
  и просыпается первым запросом — до двух минут. Нужен ответ без задержки — `min: 1`.
- **Staging** запускает только веб; `worker` и задачи по расписанию работают только на prod.
- **Сеть.** Единственный достижимый адрес — прокси. Python (`requests`, `httpx`, `urllib`,
  `boto3`) берёт его из `HTTP_PROXY`/`HTTPS_PROXY` сам. Node.js — см. [recipes-node.md](recipes-node.md).
- **Модели.** Приложение вызывает только модели из `gpu:` манифеста, остальные — 403.
  Спящая модель поднимается первым вызовом: запрос ждёт до 4 минут, дальше — 503 с
  `Retry-After: 30`. Имени нет в каталоге — 404.

## Переменные окружения процесса

| Переменная | Что |
|---|---|
| `PORT` | порт веб-процесса (тот, что в `processes.web.port`) |
| `DATABASE_URL` | Postgres, если есть `data.postgres` |
| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_ENDPOINT_URL_S3`, `AWS_REGION`, `AWS_DEFAULT_REGION`, `LOOMA_BUCKET` | бакет, если есть `data.bucket` |
| `LOOMA_APP_TOKEN`, `LOOMA_API_URL` | вызовы моделей и учёт (`/v1/...` на этом адресе) |
| `LOOMA_APP`, `LOOMA_APP_ID`, `LOOMA_APP_URL` | имя, номер и адрес приложения |
| `LOOMA_ENVIRONMENT` | `prod`, `staging` или `dev` (в `looma dev`) |
| `LOOMA_RELEASE`, `LOOMA_PROCESS`, `LOOMA_INSTANCE` | номер релиза, имя процесса, номер экземпляра |
| `HTTP_PROXY`, `HTTPS_PROXY` (и в нижнем регистре) | прокси для выхода в интернет |
| имена из `secrets:` | значения из `looma secrets set` |

Имена `PATH`, `HOME`, `PORT`, `DATABASE_URL`, `TMPDIR`, `*_PROXY` и всё на `LOOMA_`,
`AWS_`, `S3_` заняты платформой: секрет с таким именем не задать.

## Клиенты маркетплейса

- `access: clients` — к приложению пускают только вошедших на витрине маркетплейса (и
  программы с ключом клиента). Гость видит страницу входа, программа — 401.
- Каждый запрос к приложению несёт заголовок `X-Looma-Client` — псевдоним клиента
  (почты и имени нет). Свои учётные записи проекта можно оставить, можно привязать к
  этому псевдониму.
- Вызов модели «за клиента» — с тем же заголовком `X-Looma-Client`; событие учёта —
  `POST $LOOMA_API_URL/v1/charge` с `{"client", "event"}` (имя события — из `events:`).
